## 1. 오늘 내가 직접 손으로 치며 배운 점
- private, public을 통해서 메서드 안에서 불변해야할 값과 은닉화를 통해 구조 안정성을 꾀할 수 있음을 느낌. (내부 구현이 바뀌어도 외부에 미치는 영향이 최소화 되는 결합도 낮춤 가능)
- 결합도는 낮게 응집도는 높으면 좋은 코드임. (다시한번 기억!)
- Math.min, Math.max를 통해서 최소값, 최대값에 대한 보정을 통해 방어 코드 구조를 만들 수 있었음. -> 방어적 프로그래밍, 예상치 못한 입력 및 잘못된 인자, 음수 시간이 들어올때 프로그램 비정상 종료, 오작동 사전차단
- 클래스를 통해 추후 오버라이딩 같은 것들을 할때 초기값의 범위를 정하는게 매우 중요할것 같은 느낌이 들었음.
- if - else나 switch 문으로 케이스 별로 나눠서 예외처리를 통한 방어코드를 작성하려했는데, 복잡한 분기 없이 간결하게 Math.min, Math.max 쓰면 되겠다는 생각이 들었음.

- 빨간줄 뜨면 희열을 느끼는 나를 보면서 덤벙대지 말아야겠다는 생각이 들었음. 
- 메서드 구조를 할수만 있다면 단순화하는 습관이 좋을것 같다는? 생각이 들었다.

## 3. 나만의 언어로 재해석한 핵심 용어 사전
- 접근제어자: 중요한거니까 함부로 바꾸지마라. (private: 오직 해당 클래스 내부에서만 접근할 수 있어 데이터 무결성 지킴(수정, 변경 임의로 못하게))
- 정보은닉: 객체의 내부 데이터를 외부에서 직접 보거나 함부로 수정치 못하도록 숨기는 것
- 클램핑: 특정 값이 허용하는 범위를 벗어나지 않게 강제로 가두는 연산 (최댓값, 최솟값 안에 경계안에 가두기) -> Math.max(min, Math.min(value, max)) 와 같은 형태로 구현 (경계값에 대한 걸까?)
- 생성자 오버로딩: 이름은 같은데 매개 변수의 개수나 타입이 다른 생성자 여러개 선언
- 초기화: 말그대로 default값을 만들어놔서 데이터가 null이나 0 등 비정상적인 상태로 객체가 돌아다니는걸 막는 과정

## 4. 의외로 배운점
- 자바 공부할걸 왜 타입스크립트 했지?
- 오버로딩-> 같은 이름의 메서드 여러개 정의(add라고 만들면 매개변수 2개 더하기, 3개 더하기 ... 되는것
- 오버라이딩 -> 부모의 메서드를 자식클래스에서 재정의 (동물이라는 부모클래스안에 소리낸다고 해놓으면 강아지는 짖는, 고양이는 우는, 오리는 꽥꽥 거리는 등)
