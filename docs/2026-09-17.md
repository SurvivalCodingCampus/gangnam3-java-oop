## 반추의 시간

# 1. 논리의 오류
    - 이번 과정에서는 해당 이유들로 인해 논리의 오류가 발생했다.

    - 1. 식곤증
        - 식곤증으로 인해 내가 이해했던 수업 내용이 리셋되어 버린거 같았다. 진짜 머리가 백지가 되어 정보가 말소처리 되었다. 점심 식사 후 커피를 마시는것이 가장 효율적으로 판단된다.

    - 2. 개념 이해의 부족
        - 아직 단어와 단어가 가진 기능들에 있어서 익숙하지 않아 알고 있던 정보들과 새로운 정보가 혼합되어 끔찍한 혼종이 탄생했다.
        - 개념들을 구체화 하기 위해서는 나만의 정의가 새롭게 필요하다고 생각한다. 이를 위해 그림 그리기 및 타인에게 설명해줄 수 있을 수준의 기능의 구체화 작업이 필요하다고 생각한다.
        - 코드를 작성해보고 해당 동작들을 더 눈으로 익혀 개념을 이해할 순 없어도 동작의 기능에 대해서 연구해볼 필요가 있다고 생각한다.

    - 3. 내려놓음
        - 기존의 가치관들, 사고관을 잠시 내려놓고 가벼운 마음으로 보는 것이 좋을듯 싶다. 나에게는 하나의 징크스가 있다. 그것은 어떤 문장을 보면 그 문장의 어색한 부분을 고치고 싶다는 충동 및 시도가 있다. 이 행동은 비단 동어반복적이어도 이해가 갈 수 있는 문장들을 만들었던 나만의 습관이라고 생각한다. 에고를 내려놓고 새로운 세상의 문법에 적응이 필요함을 느꼈다.

    - 0. 이번주의 고행
        - 이번주는 특히나도 몸을 쓰는 일이 너무 많아 심신이 지쳤음으로 스스로 판단해본다. 같이 일하시는 반장님이 일처리를 잘 못해서 내가 월~화 이틀동안 고생한 여파라고 생각도 해본다.      (변명은 여기까지.)

# 2. 오류의 발생
    - 지금부터 어떠한 오류가 발생했는지에 대해 설명을 하도록 하겠다.

    1. 생성자의 미궁

        Cleric(String name, int hp) {
        this(name, hp, MAXMP);} 

        해당 생성자 문장에서 내가 이해한 String name, int hp 는 해당 두개의 데이터 타입이 해당 두개의 값만 수정할 수 있다는 식으로 이해했다.
        더 나아가 해당 기능들이 데이터 접근 권한을 갖는 카드 키로 인식해 생성자의 기능과 클래스의 기능을 혼동하는 상황을 마주했다.
        아마 해당 오류는 다양한 단어들의 기능과 정의가 갑자기 융합되어 이상한 나만의 정의로 변한것 같았다. 

    2. this. 와 this()의 대립

        this. 와 this() 가 같은 기능을 수행하는 것으로 착각했다. 이를 통해 미궁의 심부까지 도달했으며 빠져나올 수 없는 크레타의 미궁이 완성되었다.

    3.  개념의 내면화 실패

        생성자 초기화라는 개념과 중복코드를 줄이기 위한 자바의 기능을 이해하지 못해 미노타우르스를 만났다. 그리고 새벽 2시 아직도 미노타우르스의 뿔을 잡고 사투중이다.

# 3. 오늘의 정리
    - 부족한 이해를 정리하기 위해 ai와 2시간의 토론이후 도출해놓은 결과를 공유하는 바이다.

    1. 생성자란?
        생성자는 new를 사용해 객체를 만들 때 처음 실행되어 객체의 초기값을 설정하는 코드이다. 

        new Cleric("Titus", 30, 5);             =    객체
        
        Cleric(String name, int hp, int mp) {
        this.name = name;                       =   생성자
        this.hp = hp;
        this.mp = mp;
        }


    2. 생성자 오버로딩
        하나의 클래스에 매개변수가 다른 생성자를 여러 개 만들 수 있다.

        Cleric(String name)                     스트링 하나
        Cleric(String name, int hp)             스트링 하나, 인트 하나
        Cleric(String name, int hp, int mp)     스트링 하나, 인트 하나, 인트 하나

        Java는 전달한 값의 개수, 타입, 순서를 보고 알맞은 생성자를 호출한다.


    3. this(...)로 다른 생성자 호출
        this(...)는 같은 클래스의 다른 생성자를 호출하는 문법이다.

        Cleric(String name, int hp) {
        this(name, hp, maxMp);
        }

        내가 객체의 정보를 아래와 같이 기입하고 호출한다면

        new Cleric("Titus", 30);

        name과 hp는 이미 받았으므로 그대로 전달하고, 받지 못한 mp만 "maxMp라는 기본값"으로 채운다.

        name  → "Titus"  (받은 값)
        hp    → 30       (받은 값)
        mp    → maxMp    (기본값)

        따라서 결과적으로

        this("Titus", 30, 10);

        이 되어 3개짜리 생성자에게 초기화를 맡긴다. (3개짜리 생성자가 있을때)

    4. 왜 this(...)를 사용할까?
        - 나의 가장 큰 미로는 왜..? 였다. 그야, 하나 더 기입하는게 더 이해하기 쉽기 때문이었다. 그 러 나
        - 이미 3개짜리 생성자가 같은 초기화 작업을 하고 있다면, 기존 생성자를 재사용하여 코드 중복을 줄일 수 있다.

        - 생성자는 객체의 초기 상태를 설정하며, 여러 생성자를 만들 수 있고 this(...)를 사용하면 받은 값은 그대로 전달할 수 있으며 부족한 값은 기본값으로 채워 다른 생성자에게 초기화를 맡길 수 있다. (사실 아직도 초기화라는 것이 잘 감이 안 온다.)
