### 1.  GitHub 협업?

- 여러 명이 모여서 거대한 요리책(앱)을 만든다고 상상해 보세요. 
- 혼자 만들면 내 맘대로 하겠지만, 여러 명이 동시에 글을 쓰면 어떤 문제가 생길까요?"
- 어? 내가 쓴 글 위에 친구가 다른 글을 덮어써서 내 내용이 사라졌어!"
- "누가 어떤 요리를 만들고 있는지 서로 몰라서 우왕좌왕해요."
- 이럴 때 교통정리를 해주는 마법의 도구가 바로 GitHub입니다.
- 1. 역할 나누기 (Issue와 프로젝트 보드)이슈(Issue): 
  "오늘 우리가 해야 할 일 목록(To-Do 리스트)"을 적어두는 곳입니다. 
  (예: "계란프라이 만들기"라는 할 일 카드 만들기)
- 프로젝트 보드: 
  이 할 일들이 준비중(Todo) ➔ 요리중(In Progress) ➔ 완성(Done) 
  칸으로 스티커처럼 척척 옮겨지면서 누가 무얼 하는지 한눈에 보여줍니다.
-  2. 안전하게 따로 놀기 (Branch, 브랜치)메인 요리책(코드)에 바로 손을 대면 망칠 수 있으니까, 
     내 이름으로 된 임시 복사본 통로(Branch)를 만듭니다. 거기서 마음껏 고치고 실험해 봐요.
-  3. 검사받고 합치기 (PR과 Merge)내 복사본에서 요리를 다 만들었으면 대장님(팀원)께 
   "저 이거 다 만들었는데 메인 요리책에 합쳐주세요!"라고 요청하는 편지를 보냅니다. 
   이걸 PR(Pull Request)이라고 해요.
   팀원들이 코드를 살펴보고 문제가 없으면 메인 요리책에 합쳐줍니다(Merge). 
   합쳐지는 순간, 아까 그 할 일 카드(Issue)는 자동으로 '완료(Closed)' 처리됩니다!
-  4. 글자가 꼬였을 때! (충돌, Conflict)나와 친구가 동일한 줄의 글을 동시에 고쳤다면 컴퓨터가 
   당황해서 "어느 쪽 말을 들어야 할까요?" 하고 빨간불을 켭니다. 이게 바로 충돌(Conflict)입니다. 
   이때는 AI의 도움을 받거나 서로 상의해서 올바른 문장으로 딱 고쳐주면 해결됩니다.

### 🛠️ 꼭 알아야 할 핵심 Git & GitHub CLI 명령어 정리
  터미널이나 명령 프롬프트에서 마우스 클릭 없이 빠르게 협업할 수 있게 도와주는 명령어 모음입니다.
기능명령어설명
  로그인     gh auth login       터미널에서 내 GitHub 계정과 연동(로그인)합니다.   
  이슈 생성  gh issue create --title "제목" --body "내용"   터미널 창에서 웹페이지에 들어가지 않고도 새로운 할 일(이슈)을 뚝딱 만듭니다.   
  브랜치 변경 git checkout -b <브랜치이름>      새로운 작업용 복사본(브랜치)을 만들고 그 안으로 이동합니다.
  코드 올리기 git add .git commit -m "메시지"git push -u origin <브랜치>       내가 수정한 코드를 저장소 대기소에 넣고, 기록을 남긴 뒤, 
  내 브랜치 이름으로 인터넷(GitHub)에 업로드합니다.   
  PR 생성   gh pr create --base develop --title "제목" --body "내용"     "내 브랜치의 코드를 개발(develop) 브랜치에 합쳐주세요!" 
  하고 PR 편지를 보냅니다.

  머지(합치기)	gh pr merge --merge  검토가 끝난 PR을 승인해서 메인 코드에 완전히 합치고 연동된 이슈를 자동 종료합니다.
