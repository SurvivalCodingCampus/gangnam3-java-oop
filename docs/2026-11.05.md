### 1.  Result 패턴 (요약 설명)
우리가 게임을 하거나 편지를 보낼 때, 결과는 항상 성공하거나 실패 둘 중 하나예요.
- 성공했을 때: 갖고 싶던 선물(데이터)을 받아요!
- 실패했을 때: 와이파이가 끊겼는지(네트워크 오류), 상자가 비었는지(404 에러) 이유를 정확히 알아야 다시 도전할 수 있어요.
옛날 방식(try-catch)은 문제가 터졌을 때만 엉겁결에 대처했다면, Result 패턴은 "성공했을 때는 선물 상자(Success), 실패했을 
때는 오류 표지판(Error)"을 반환하도록 처음부터 딱 봉인(sealed interface)해서 만드는 방식이에요!
이 방식을 쓰면 코딩할 때 실수로 에러 처리를 깜빡하는 일을 마법처럼 막아준답니다.

### 2. 핵심 명령어 및 주요 개념정리
-  명령어 / 개념                                  설명 
   sealed interface Result<out D, out E>   성공(Success) 또는 실패(Error) 
                                           두 가지 경우로만 결과 타입을 엄격하게 제한(봉인)합니다.
   Result.Success(data)                    작업이 성공했을 때 실제 결과 데이터(data)를 담아 반환하는 클래스입니다.
   Result.Error(error)                     작업이 실패했을 때 에러 종류(error)를 담아 반환하는 클래스입니다.
   enum class NetworkError                 NO_INTERNET, CLIENT_ERROR, SERVER_ERROR, TIMEOUT 등 
                                           발생 가능한 네트워크 에러의 종류를 나열한 목록입니다.
   when (result)                           Result 결과를 받아 성공과 실패, 그리고 세부 에러 상황에 따라 분기 처리를 강제하는 구문입니다.
   Unit / Nothing                          Unit은 반환값이 없는 정상 종료를, 
                                           Nothing은 성공/실패 타입 중 데이터가 존재할 수 없음을 나타내는 특별한 타입입니다.

### 연습과제 1.
package com.example.pokemon.core

// 1. 에러 종류 정의
enum class NetworkError {
    NO_INTERNET,   // 인터넷 연결 없음
    SERVER_ERROR,  // 5xx 서버 에러
    CLIENT_ERROR,  // 4xx 클라이언트 에러 (예: 404 Not Found)
    TIMEOUT,       // 시간 초과
UNKNOWN        // 기타 알 수 없는 에러
}

// 2. Result 패턴 정의 (Sealed Interface)
sealed interface Result<out D, out E> {
    data class Success<out D>(val data: D) : Result<D, Nothing>
    data class Error<out E>(val error: E) : Result<Nothing, E>
}

### 연습문제 2.
package com.example.pokemon.repository

import com.example.pokemon.core.NetworkError
import com.example.pokemon.core.Result
import com.example.pokemon.data_source.PokemonDataSource
import com.example.pokemon.model.Pokemon
import com.example.pokemon.mapper.toModel
import java.net.SocketException
import kotlinx.coroutines.TimeoutCancellationException

// 3. Repository 인터페이스 및 구현체
interface PokemonRepository {
    suspend fun getPokemon(name: String): Result<Pokemon, NetworkError>
}

class PokemonRepositoryImpl(
    private val dataSource: PokemonDataSource
) : PokemonRepository {

    override suspend fun getPokemon(name: String): Result<Pokemon, NetworkError> {
        return try {
            val response = dataSource.getPokemon(name)

            // HTTP 상태 코드가 성공(200~299)이 아닌 경우
            if (!response.isSuccessful) {
                // 400번대 클라이언트 에러 처리 (예: 404 Not Found)
                return Result.Error(NetworkError.CLIENT_ERROR)
            }

            // DTO 응답 바디 추출
            val dto = response.body() 
                ?: return Result.Error(NetworkError.SERVER_ERROR)

            // DTO -> Model 변환 후 성공 리턴
            Result.Success(dto.toModel())

        } catch (e: SocketException) {
            Result.Error(NetworkError.NO_INTERNET)
        } catch (e: TimeoutCancellationException) {
            Result.Error(NetworkError.TIMEOUT)
        } catch (e: Exception) {
            Result.Error(NetworkError.UNKNOWN)
        }
    }
}

4. 검증 테스트 코드 (JUnit5 + runTest)

package com.example.pokemon.repository

import com.example.pokemon.core.NetworkError
import com.example.pokemon.core.Result
import com.example.pokemon.data_source.FakePokemonDataSource
import kotlinx.coroutines.test.runTest
import org.junit.jupiter.api.Assertions.assertEquals
import org.junit.jupiter.api.Assertions.assertTrue
import org.junit.jupiter.api.Test

class PokemonRepositoryTest {

    @Test
    fun `존재하지_않는_포켓몬_검색_시_CLIENT_ERROR가_반환된다`() = runTest {
        // Given: 404 Not Found 응답을 주는 FakeDataSource 준비
        val repository = PokemonRepositoryImpl(FakePokemonDataSource())

        // When: 오타가 난 포켓몬 이름 검색 ("dittooo")
        val result = repository.getPokemon("dittooo")

        // Then: 실패 타입(Result.Error) 및 구체적인 에러(CLIENT_ERROR) 검증
        assertTrue(result is Result.Error)
        assertEquals(NetworkError.CLIENT_ERROR, (result as Result.Error).error)
    }
}

###  AI 질문 및 학습인사이트(공통)
-  연습 코드를 기초교육과정에 맞게 에러없이 수정하여 Pokemon게임을 완성 하셔요.
 
-  기존 예외 처리(try-catch)의 한계 극복서버 통신 시 단순히 성공과 실패를 나누는 것을 넘어, 
   네트워크 단절(NO_INTERNET), 타임아웃(TIMEOUT), 클라이언트 에러(CLIENT_ERROR, 404 등), 서버 에러(SERVER_ERROR, 5xx) 등 
   다양한 실패 원인을 세밀하게 다루어야 하는 필요성을 배웠습니다.   
-  Result 패턴의 도입과 구조 (sealed interface)성공 시 데이터를 담는 Success와 실패 시 에러 정보를 담는 Error를 
   하나의 공통 타입으로 묶어주는 Result 패턴을 학습했습니다.   
-  코틀린의 sealed interface를 활용하여 타입 안정성을 높이고, 컴파일러가 모든 에러 케이스 처리를 강제하도록 설계하는 법을 익혔습니다.
-  Repository 계층의 에러 핸들링 및 패턴 매칭 (when)PokemonRepositoryImpl에서 API 응답의 성공 여부(isSuccessful)나 예외 
   발생 시점을 잡아서 적절한 NetworkError(CLIENT_ERROR 등)로 매핑하여 리턴하는 구조를 구현했습니다.   
-  호출부에서 when 분기 처리를 통해 모든 에러 상황에 대한 대응 로직을 누락 없이 작성할 수 있음을 확인했습니다.
