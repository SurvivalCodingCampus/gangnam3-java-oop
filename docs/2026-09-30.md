## 용어정리

### 추상 클래스

- is-a
- 하위 클래스의 필드 중에서 공통적으로 사용되는 필드를 상위 클래스로 만들어 상속의 개념으로 필드를 사용하는 방법
- 추상 메소드는 abstract을 붙이고 추상 메소드가 있으면 추상 클래스로 abstract를 붙임
- 클래스로 생성자와 캡슐화 (getter & setter) 필요함
- 추상 클래스는 인스턴스화 (new)할 수 없음

### 인터페이스

- can-do/ is-a
- 추상 클래스 중에서 추상 메소드만 가지고 있는 것
- getter&setter로만 사용 가능
- implements로 추상 메소드를 사용하는 가장 상위 클래스에 메소드를 받는 인터페이스의 필드를 override함 (getter&setter)
- 복수의 인터페이스를 부모에 두는 다중 상속이 가능

### 추상 클래스와 인터페이스를 하는 이유

- 부모 클래스를 만들때 상속의 재료를 다른 개발자들이 사용할 수 있게 안내 도구를 제공하는 기능
