## 1. 배운 점
- 인터넷 편지(JSON)와 불완전한 세상:
  서버에서 받아오는 데이터(JSON)에는 간혹 값이 텅 비어 있거나(null), 예상치 못한 문제가 숨어 있을 수 있습니다.
  만약 이 불안정한 데이터를 그대로 앱에 사용하면 프로그램이 갑자기 멈추거나 꺼져버리는 대참사가 일어납니다.   
- 방패막이 친구, DTO (Data Transfer Object):
  서버가 보내주는 거칠고 불안정한 데이터를 안전하게 받아내기 위한 '임시 택배 상자(DTO)'입니다. 
  DTO의 모든 칸은 혹시 모를 빈 값에 대비해 텅 비어 있어도 안전하도록(Nullable) 설계합니다.   
- 알맹이만 쏙 뽑아내는 Mapper(변환기):
  안전하게 받아온 DTO 택배 상자에서 앱이 꼭 필요로 하는 깨끗하고 완벽한 알맹이만 골라내어 
  '진짜 우리 앱의 물건(Model Class)'으로 바꿔주는 마법의 조립 대가입니다.

## 주요 명령어 및 개념 정리
-  DTO (Data Transfer Object): 
   서버에서 온 JSON 데이터를 앱이 터지지 않도록 안전하게 받아주는 중간 데이터 전달용 객체입니다. 
   모든 필드를 null이 될 수 있게(?) 만듭니다.   
-  Model Class (도메인 모델): 
   앱 안에서 실제로 사용할, null이 없고 깔끔하게 정리된 순수한 데이터 객체입니다.   
-  Mapper (확장 함수): 
   DTO 객체를 Model 객체로 변환해 주는 유틸리티 기능입니다. 
   코틀린의 확장 함수(fun Dto.toModel()) 형태로 주로 작성합니다.   
-  ?: (Elvis Operator): 
   만약 값이 null(비어 있음)이라면 대신 다른 기본값(예: "제목 없음", 0, false)을 채워 넣도록 도와주는 안전 장치 연산자입니다.

##  DTO 가 필요한 이유
  - Model Class 는 non-nullable 값만 가지고 있도록 한다
  - Json 데이터는 null 값을 포함할 수 있음 (문서에 명시되어 있지 않더라도…)
  - Map -> Model Class 변환시 null 값 등의 예외를 사전에 걸러내기 용이함
  - 불완전한 코드가 포함될 것 같다면 DTO를 도입하자
  - Json 값에 예외가 없다면 반드시 DTO를 도입할 필요는 없다

import kotlinx.serialization.json.Json

@Serializable
      data class PokemonDto(
         val id: Int? = null,
         val name: String? = null,
         val height: Int? = null,
         val weight: Int? = null
         ) {
                companion object {
                    fun fromJson(json: String): PokemonDto {
                        return Json.decodeFromString(serializer(), json)
                                }
                    }
        }
