# DataSource

## 용어 정리

- `DataSource`: `데이터` 조작을 `캡슐화` 한 객체

## 정리

- `DataSource의 역할과 캡슐화`
  - `UI` 나 `비즈니스 로직` 에 `File.readText()` `Json.decode()` 및 `네트워크 통신` 코드가 섞이면 유지보수가 불가능해진다.
  - `DataSource` 는 지저분한 기술 코드를 숨기는 껍데기로써 외부 데이터 저장소와 직접 통신하는 역할을 수행한다.
  - `Raw 데이터` 수신 및 처리 그리고 데이터를 `Create` `Read` `Update` `Delete` 하는 작업을 수행한다.
  - 데이터는 `다양한` 형태가 존재한다.
  - 일관된 패턴은 `유지보수성` 과 `협업` 효율을 향상시킨다.

- `DataSource 네이밍 패턴`
  - `LocalUserDataSource` `RemoteUserDataSource` `CachedUserDataSource` 등 접두어를 통해 저장소 유형을 표시한다.
  - `RoomUserDataSource` `RetrofitUserDataSource` `SharedPrefsUserDataSource` 등 구현 기술이 명확한 경우 해당 이름을 사용한다.

- `DataSource의 종류`
  - File
  - JSON
  - XML
  - CSV
  - RDBMS (MySQL, PostgreSQL, supabase 등 관계형 DB)
  - NoSQL (MongoDB, Firebase Firestore)
  - 외부 네트워크/API
  - 그외 등등
