## 1. 배운 점

### 예외.

- 프로그렘을 설계할  때.
  실행시에 예외 상황이 발생 할 가능성이 있는 것을 예측하여, 사전에 예외처리가
  되도록 할 필요가 있음.
  - 비유하자면: 신나게 미끄럼틀을 타러 갔는데 갑자기 고장이 났거나 뚝 끊겨 있으면 
    다칠 수 있겠죠? 프로그램도 마찬가지로 예상치 못한 사고(에러)가 나면 갑자기 멈춰버려요. 
    이때 "어라? 문제가 생겼네? 당황하지 말고 이렇게 수습하자!" 하고 막아주는 방어막이 바로 
    예외 처리(Exception Handling)예요.

- 코틀린에서의 사용법 (try-catch):
  try 상자 안에는 "일단 시도해 볼 위험한 일"을 넣어요. (예: 0으로 어떤 수를 나누거나, 없는 파일을 열 때)
  만약 문제가 생기면 프로그램이 터지는 대신 catch 상자가 나타나서 "아쿠! 이런 문제가 생겼군요. 
  대신 이걸로 해결할게요!"라며 안전하게 받아쳐 줍니다.

- 파일 조작 (컴퓨터 서랍장에 일기 쓰기)
  비유하자면: 우리가 방에 노트를 꺼내서 일기를 쓰고, 상자에 보관했다가 나중에 다시 꺼내 읽는 것과 같아요. 
  컴퓨터 속 하드디스크라는 거대한 서랍장에 글자를 쓰고 읽는 것을 파일 조작이라고 해요.
  핵심 기능:
    파일 쓰기: 컴퓨터 서랍장에 새로운 공책을 펼치고 "오늘 날씨 맑음"이라고 꾹꾹 눌러 담아 저장하는 것.
    파일 읽기: 서랍장에서 그 공책을 스윽 꺼내서 "아, 이런 내용이 적혀 있었구나!" 하고 눈으로 확인하는 것.
    코틀린에서는 복잡한 준비 운동 없이도 몇 줄 안 되는 마법의 주문(readText() 등)으로 파일을 아주 쉽게 열고
    닫을 수 있답니다.

- 여러 가지 데이터 형식
  - 컴퓨터끼리 서로 이야기를 주고받거나 정보를 저장할 때, 선물을 포장하는 것처럼 정보를 담는 모양(형식)이 여러 가지가 있어요. 
    대표적인 3총사를 알아볼까요?
    - 텍스트 (Text - 순수한 편지지):
      그냥 글자 그대로 적힌 가장 기본적인 형식이에요. (예: .txt 파일) 누구나 읽을 수 있지만, 안의 내용이 이름인지 나이인지 컴퓨터는 스스로 알기 어려워요.
    - CSV (줄줄이 소시지 형식):
      쉼표(,)를 기준으로 데이터를 콤팩트하게 줄 세워 놓은 형식이에요.
      예: 홍길동,13,서울 (이름, 나이, 사는 곳을 쉼표로 착착 구분해서 엑셀처럼 표로 보기 쉽게 만들 때 씁니다.)
    - JSON (이름표가 붙은 선물 상자):
      요즘 세상에서 가장 인기가 많은 형식이에요! 데이터에 "이름은 이거야", "나이는 이거야"라고 예쁜 이름표(Key-Value)를 붙여서 택배 상자에 담아 보내는 방식이에요. 
      컴퓨터와 스마트폰이 서로 대화할 때 이 JSON 상자를 가장 많이 주고받는답니다.

-  문법 에러 (Syntax Error)
   뜻: 프로그래밍 언어가 가진 규칙(맞춤법)을 틀렸을 때 발생하는 에러입니다.
   언제 발생하나요? 코드를 실행하기 전(컴파일 단계)에 빨간 줄이 쫙 뜨며 아예 실행조차 되지 않습니다.
   비유하자면: 한글을 쓸 때 "사과가 먹었어"처럼 조사나 단어 배치가 완전히 틀려서 상대방이 글자 자체를 읽을 수 없는 상태와 같습니다. 오타를 고치면 바로 해결됩니다.

- 실행 시 에러 (Runtime Error)
  뜻: 문법은 다 맞아서 프로그램이 시작되었지만, 실제로 실행하는 도중에 예상치 못한 사고가 나서 멈춰버리는 에러입니다.
  언제 발생하나요? 프로그램이 열심히 돌아가는 중간에 발생합니다. (예: 0으로 어떤 숫자를 나누려고 할 때, 존재하지 않는 파일을 억지로 열려고 할 때 등)
  비유하자면: 자동차 면허 시험에 합격해서 차를 운전해 도로로 나갔는데(문법은 정상), 가다가 갑자기 타이어가 펑크나서 멈춰버린 상황과 같습니다.

- 논리 에러 (Logic Error)
  뜻: 에러 메시지도 안 뜨고 프로그램도 끝까지 잘 실행되지만, 우리가 원했던 결과와 엉뚱한 결과가 나오는 에러입니다.
  언제 발생하나요? 프로그래머가 생각한 논리나 계산 공식이 잘못되었을 때 발생합니다. 컴퓨터는 명령한 그대로 일했을 뿐이기 때문에 에러를 띄워주지 않습니다.
  비유하자면: 수학 시험 문제를 풀 때 덧셈을 해야 하는데 실수로 뺄셈을 해서 답을 다 틀린 것과 같습니다. 글자나 식은 멀쩡하지만 결과가 틀린 경우입니다.

- 프로그램이 실행되는 도중에 발생하는 대표적인 실행 시 에러(Runtime Error)이자 예외(Exception) 상황들입니다.
  메모리 부족 (Out of Memory): 프로그램이 실행되면서 너무 많은 데이터를 한 번에 처리하느라 컴퓨터가 가진 기억 공간(메모리)의 한계를 넘어섰을 때 발생합니다.
  파일을 찾을 수 없음 (File Not Found): 프로그램은 정상적으로 시작되었지만, 지정한 위치에 막상 읽으려는 파일이 존재하지 않을 때 발생합니다.
  네트워크 통신 불가: 인터넷 선이 뽑혔거나 서버에 문제가 생겨 외부와 데이터를 주고받지 못할 때 발생합니다.
  이러한 에러들은 코드를 작성할 때(문법 에러)는 알 수 없고, 프로그램이 실제로 굴러가는 동안 외부 환경이나 예상치 못한 변수 때문에 발생합니다. 
  그렇기 때문에 try-catch 같은 예외 처리 방어막을 쳐서 프로그램이 갑자기 멈추는 것을 막아주어야 합니다.

###에러
syntax error, runtime error, logic error 의 3종류
예외처리를 할 때는, runtime error를 대처한다

###예외의 종류
API에는 여러가지 예외적 상황을 표현하는 예외 클래스가 준비되어 있다.
예외 클래스를 상속하여 오리지날 예외 클래스를 정의할 수 있다.

###예외 처리
try-catch 문을 사용하면, try 블록 내에 예외가 발생했을 때 catch 블록에서 처리가 옮겨진다
finally 블록으로 나중에 꼭 해야하는 처리를 할 수 있다
throw 문을 사용하면 임의로 예외를 발생시킬 수 있다



- 프로그램이 실행되는 도중 문제가 생겼을 때 안전하게 대처하기 위해 사용하는 try-catch 예외 처리의 흐름.
  try-catch 안전망의 하루
  try 상자 (일단 시도해 보기):
  위험하거나 문제가 생길지도 모르는 일을 일단 시도해 보는 안전 상자예요.
  비유하자면, "이번에 새로 산 롤러코스터를 타고 언덕을 내려가 볼게!" 하고 출발하는 것과 같아요. 평소에는 무사히 잘 지나가지만, 가끔 도중에 장애물이 나타날 수도 있죠.
  catch 상자 (문제가 생겼을 때 구출하기):
  try 상자 안에서 일을 하다가 쿵! 하고 에러(예외)가 발생하면, 프로그램이 터져서 멈추는 대신 곧바로 catch 상자가 출동해요.
  비유하자면, 롤러코스터가 가다가 멈췄을 때 안전요원이 짠 하고 나타나서 "아쿠, 바닥에 돌멩이가 있어서 멈췄군요! 대신 안전 매트를 깔아줄 테니 이쪽으로 내려오세요~"
  라며 수습해 주는 것과 같아요.

  -  전체 흐름 요약
  출발: 코드가 try 블록 안에서 위풍당당하게 실행을 시작합니다.
  갈림길:
    아무 문제 없을 때: try 안의 코드가 끝까지 무사히 실행되고, catch는 그냥 조용히 넘어갑니다.
    문제가 생겼을 때: 갑자기 에러가 팡 터지면서 try의 남은 코드는 무시되고, 곧바로 아래에 있는 catch 블록으로 텔레포트하듯 이동합니다.
  마무리: catch 안에서 에러에 대한 해결책이나 안내를 처리하고 나면, 프로그램이 멈추지 않고 그 다음 코드로 안전하게 계속해서 달릴 수 있게 됩니다.
  이처럼 try-catch는 프로그램이 갑자기 튕기거나 꺼지는 것을 막아주는 든든한 비상 탈출구랍니다!

- 직접 에러를 해결하지 않고, 나를 부른 사람(호출자)에게 "이 에러 네가 처리해!" 하고 책임을 떠넘기는 throw에 대해.
  - 직접 처리 (try-catch):
    심부름꾼이 마트에 갔는데 우유가 다 떨어졌어요. 이때 심부름꾼이 직접 "어떡하지?" 하고 고민하다가 근처 슈퍼로 뛰어가는 등 자기가 직접 문제를 해결하는 거예요.
  - 위임하기 (throw):
    심부름꾼이 마트에 갔는데 우유가 없어요. 이때 심부름꾼은 해결하려 하지 않고, 집에서 기다리는 공주님(함수를 호출한 사람)에게 곧바로 전화해서 "공주님! 우유가 없어서 못 사 오겠어요! (Throw Exception)" 하고 에러를 뻥 차버리는(미루는) 거예요.
- throw는 내가 감당하기 힘들거나, 이 에러는 나를 시킨 사람(상위 함수)이 직접 어떻게 할지 결정해야 할 때 "여기 에러 났어요!" 하고 책임을 쿨하게 넘겨주는 마법의 키워드.

- 여러 가지 문제가 뻥뻥 터질 수 있어요. 이때 아무 에러나 다 잡는 게 아니라, "내가 원하는 특정 에러만 콕 집어서 잡아내는 방법".
  
- 특정 예외만 콕 집어내기 (맞춤형 방어막)
  - 비유하자면: 학교에 갔는데 어떤 친구는 배가 아프고(1번 문제), 어떤 친구는 연필이 부러졌어요(2번 문제). 선생님이 "다 아프지?" 하고 대충 넘어가는 게 아니라, "배 아픈 사람은 보건실에 가고, 연필 부러진 사람은 연필깎이를 써!" 하고 문제마다 딱 맞는 해결책을 주는 것과 같아요.
  - 코틀린에서의 사용법:
    try 상자 안에서 어떤 에러가 날지 예상해서, catch를 여러 개 만들거나 특정 에러 이름(NumberFormatException, NullPointerException 등)을 적어둘 수 있어요.

- 에러가 나든 안 나든 "끝나기 전에 무조건 꼭 해야 하는 마무리 일"이 생기기 마련입니다. 이럴 때 사용하는 finally 블록.
  - finally (무조건 뒷정리 구역)
  - 비유하자면: 친구들과 놀이방에서 신나게 장난감을 가지고 놀았어요. 중간에 다투거나(에러 발생) 무사히 잘 놀았든 상관없이, 놀이가 끝나면 반드시 장난감을 정리하고 불을 꺼야 하는 것과 같아요.
  - 코틀린에서의 역할:
    - try 안에서 코드를 실행하다가 에러가 나든, 안 나고 무사히 넘어가든, 마지막에 finally 블록은 무조건 실행됩니다.
    - 주로 열어두었던 파일을 닫거나, 인터넷 연결을 끊는 등 자원을 반납하고 뒷정리를 하는 용도로 사용합니다.
- 요약하자면
  finally는 "성공하든 실패하든 내가 책임지고 무조건 실행하고야 마는 궁극의 뒷정리 도우미".

- 오리지널 예외 클래스(Custom Exception Class)를 만드는 방법.
  - 나만의 맞춤형 에러 이름표 만들기
    - 비유하자면: 세상에 수많은 아픔이나 사고가 있지만, 게임을 하다가 "앗, 내 캐릭터 체력이 바닥났어!"라거나 "아이스크림이 바닥에 떨어졌어!"처럼 우리들만의 특별한 상황을 나타내는 이름표가 필요할 때가 있죠?
    - 자바나 코틀린이 기본으로 제공하는 에러(0으로 나누기, 파일 없음 등) 외에도, 우리 프로그램만의 특별한 규칙이 깨졌을 때 쓸 수 있는 나만의 에러 이름표를 직접 만드는 것을 '오리지널 예외 클래스 정의'라고 해요.

- 제시해주신 코드를 실행했을 때 발생하는 런타임 에러 확인과, try-catch문을 사용해 예외를 안전하게 처리하고 기본값(0)을 할당하는 코드.
  - try-catch문 자체를 값을 반환하는 표현식(Expression)으로 쓸 수 있습니다. 따라서 변환이 성공하면 원래 숫자가 num에 들어가고, 소수점 문자열이라 에러가 터지면 catch 블록 안의 0이 리턴되어 안전하게 num에
    쏙 들어가게 됩니다.

#### 파일 조작의 기본 순서.
- 컴퓨터 서랍장에서 일기장을 다루는 3단계 순서
  - 파일을 연다 (Open)
    - 비유하자면, 책상 서랍을 열고 내가 읽거나 쓰고 싶은 일기장을 꺼내서 표지를 펼치는 것과 같아요. 컴퓨터에게 "이 경로에 있는 파일을 가져와 줘!" 하고 통로를 여는 단계입니다.
  - 파일을 읽거나 쓴다 (Read / Write)
    - 펼친 일기장에 새로운 내용을 펜으로 꾹꾹 눌러 담거나(쓰기), 적혀 있는 글을 눈으로 슥슥 읽어보는(읽기) 실제 작업 단계입니다.
  - 파일을 닫는다 (Close)
    - 다 읽거나 썼으면 일기장을 착 덮어서 다시 서랍 속에 안전하게 집어넣는 것과 같아요.
    - 왜 닫아야 할까요? 컴퓨터가 파일을 연 채로 내버려 두면 기억 공간(메모리)이 낭비되거나 파일이 망가질 수 있기 때문에, 작업이 끝나면 반드시 닫아서 뒷정리를 해주어야 한답니다!

- 요구사항을 만족하는 DefaultFileOperations 클래스를 코틀린(Kotlin)으로 작성해 드립니다.
- 파일을 복사할 때는 원본 파일의 존재 여부를 먼저 확인하여 FileNotFoundException을 발생시키고, 파일을 열고 읽은 뒤 안전하게 닫는(use 함수 등 활용) 구조로 구현합니다.

#### 여러 가지 데이터 형식과 직렬화에 대한 내용

-  여러 가지 데이터 형식 (정보를 담는 다양한 포장지)
   컴퓨터가 서로 이야기를 나누거나 정보를 저장할 때 쓰는 대표적인 형식들이에요.
      - CSV 형식 (줄줄이 소시지):
        데이터들을 콤팩트하게 쉼표(,)로 착착 구분해서 줄 세워 놓은 형식이에요. 엑셀 표처럼 보기 쉽게 만들 때 주로 사용합니다.
      - Properties 형식 (이름표와 짝꿍):
      - Properties 클래스를 사용하여 키(key)와 값(value)의 쌍으로 읽고 쓸 수 있는 형식입니다. (예: data.properties 파일처럼 열쇠와 자물쇠처럼 딱 맞아떨어지는 설정 정보를 저장할 때 씁니다.)
      - XML 형식:
        태그(꺽쇠 < >)를 사용하여 정보를 꼼꼼하게 감싸서 구조를 표현하는 형식입니다.
      - JSON 형식 (가장 인기 많은 선물 상자):
        현대 인터넷(네트워크) 통신에서 가장 많이 사용되고 있어요!
        XML에 비해 용량이 훨씬 적어 가볍습니다.
        대괄호 [ ] 로는 리스트(목록)를, 중괄호 { } 로는 객체(묶음)를 표현합니다.
        키(key): 값(value) 형태로 정보를 깔끔하게 정리합니다.

- 컴퓨터 세계에서의 '직렬화(Serialization)'란?
    - 뜻: 내가 만든 복잡한 데이터 구조나 객체들의 상태를, 나중에 다시 똑같이 꺼내 쓸 수 있도록 저장하거나 통신하기 쉬운 포맷으로 쭉 펴서 변환하는 과정을 의미해요.
    - 주의할 점: 클래스 내부의 필드(상자 안의 내용물)에 또 다른 클래스가 들어있다면, 그것들도 빠짐없이 모두 직렬화 처리를 해 주어야 합니다.
    - 포맷의 확장: 옛날에는 컴퓨터만 읽을 수 있는 '바이너리(이진 데이터) 직렬화'를 많이 썼지만, 현대 개발에서는 사람이 눈으로 직접 읽을 수 있는 
    텍스트 포맷(JSON 등)으로 변환하는 것도 직렬화의 커다란 범주에 속한답니다!
    - 직렬화(Serialization)'란 : 주로 서버와 Json 으로 통신을 할 것이기 때문에 Json 직렬화를 기본으로 한다.
- 서버와 데이터를 주고받을 때 핵심이 되는 직렬화(Serialization)와 역직렬화(Deserialization)의 개념.
  - 직렬화와 역직렬화란?
    직렬화 (클래스 ➡️ JSON):
    내가 만든 복잡한 객체(예: 게임 캐릭터 정보, 회원 정보 등)를 인터넷 통신에 알맞게 사람이나 컴퓨터가 읽기 쉬운 JSON 형태의 문자열로 쭉 펴서 변환하는 것을 말해요. 주로 서버와 JSON으로 통신할 때 이 직렬화를 기본으로 사용한답니다.
    - 역직렬화 (JSON ➡️ 클래스):
    반대로 서버로부터 날아온 JSON 문자열(택배 상자)을 받아서, 프로그램 안에서 다시 원래의 객체(클래스) 모양으로 척척 조립해 되돌리는 과정을 의미해요.
  - 요약하자면
    - 직렬화: 살림살이(객체)를 택배 상자(JSON)에 차곡차곡 포장해서 보내기 좋게 만드는 것!
    - 역직렬화: 도착한 택배 상자(JSON)를 뜯어서 원래 살림살이(객체)들로 다시 짠 하고 꺼내 쓰는 것.
