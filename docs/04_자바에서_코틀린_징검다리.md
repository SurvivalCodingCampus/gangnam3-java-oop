# Java에서 Kotlin으로: 1시간 징검다리

이 문서는 `docs/01_인스턴스_클래스_캡슐화_복습.md`와
`docs/02_상속_추상클래스_인터페이스_다형성.md`를 학습한 학생이
기존 Java 코드를 Kotlin 코드로 옮겨 보는 1시간 수업 자료입니다.

새 언어를 처음부터 모두 배우는 시간이 아닙니다. 이미 알고 있는
`Hero`, `Cleric`, `SuperHero`의 코드를 기준으로 Java와 Kotlin의 차이를
빠르게 확인하고, Kotlin에서 특히 중요한 프로퍼티와 null 안전성을
직접 사용해 보는 것이 목표입니다.

## 이 수업의 목표

수업이 끝난 뒤 다음을 할 수 있으면 됩니다.

- Java 클래스를 Kotlin 클래스의 기본 형태로 옮길 수 있습니다.
- Java의 필드, getter, setter가 Kotlin 프로퍼티로 어떻게 바뀌는지 설명할 수 있습니다.
- `val`, `var`, `private set`, 사용자 정의 접근자를 구분할 수 있습니다.
- Java의 생성자 오버로드를 Kotlin의 기본 인자와 이름 있는 인자로 바꿀 수 있습니다.
- Kotlin의 `open`, `override`, `:` 문법으로 상속과 오버라이드를 작성할 수 있습니다.
- nullable 타입, 안전 호출, Elvis 연산자를 사용할 수 있습니다.
- Java와 Kotlin에서 같은 개념은 문법 차이를 코드로 비교할 수 있습니다.

## 0. 시작하기 전에

### 파일 위치

Java 파일이 다음 위치에 있었다고 가정합니다.

```text
src/main/java/com/survivalcoding/day01_class_instance/Hero.java
```

Kotlin 파일은 같은 패키지를 사용하여 다음 위치에 둘 수 있습니다.

```text
src/main/kotlin/com/survivalcoding/day01_class_instance/Hero.kt
```

Kotlin 파일의 패키지도 Java와 같습니다.

```kotlin
package com.survivalcoding.day01_class_instance
```

패키지 위치가 같아도 Java와 Kotlin 파일은 별도의 소스 파일입니다.
처음에는 Java 클래스를 한 번에 삭제하거나 교체하지 말고, Kotlin 파일에서
같은 동작을 작은 예제로 옮겨 보세요.

### 가장 먼저 기억할 문법

```java
public class Hero {
    private String name;

    public String getName() {
        return name;
    }
}
```

```kotlin
class Hero(val name: String)
```

두 코드 모두 이름을 가진 `Hero` 객체를 만들 수 있습니다. Kotlin은
생성자 매개변수 앞에 `val` 또는 `var`를 붙이면 그 매개변수를 프로퍼티로
만들 수 있기 때문에 Java보다 코드가 짧습니다.

```kotlin
val hero = Hero("홍길동")
println(hero.name)
```

Kotlin에서는 세미콜론을 보통 쓰지 않고, `public`도 기본 접근 지정자이므로
생략합니다.

## 1. `Hero`로 보는 클래스와 프로퍼티

### 1-1. Java의 필드와 getter/setter

Java에서는 필드를 `private`으로 숨기고 getter와 setter를 통해 접근하는
방식으로 캡슐화를 시작했습니다.

```java
public class Hero {
    private String name;
    private int hp;

    public Hero(String name, int hp) {
        this.name = name;
        this.hp = hp;
    }

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }

    public int getHp() {
        return hp;
    }

    public void setHp(int hp) {
        this.hp = hp;
    }
}
```

사용하는 쪽에서는 메서드를 호출합니다.

```java
Hero hero = new Hero("홍길동", 100);
System.out.println(hero.getName());
hero.setHp(50);
```

### 1-2. Kotlin의 프로퍼티

Kotlin에서는 필드와 getter/setter를 합쳐 **프로퍼티(property)** 로 표현할
수 있습니다.

```kotlin
class Hero(
    var name: String,
    var hp: Int,
)
```

사용하는 코드는 다음과 같습니다.

```kotlin
val hero = Hero("홍길동", 100)
println(hero.name)
hero.hp = 50
```

`hero.name`을 작성한다고 해서 캡슐화가 사라지는 것은 아닙니다. Kotlin은
프로퍼티에 접근할 때 필요한 getter 또는 setter를 호출합니다. 즉 다음 두
코드는 목적이 비슷합니다.

| Java | Kotlin |
| --- | --- |
| `hero.getName()` | `hero.name` |
| `hero.setName("이순신")` | `hero.name = "이순신"` |
| `hero.getHp()` | `hero.hp` |
| `hero.setHp(50)` | `hero.hp = 50` |

JVM으로 컴파일할 때 Kotlin의 공개 프로퍼티에는 Java에서 사용할 수 있는
접근자 메서드가 만들어집니다. Kotlin 코드에서는 프로퍼티 문법을 사용하고,
Java 코드에서는 getter/setter 형태로 보게 됩니다.

### 1-3. 생성자 매개변수와 프로퍼티는 다릅니다

생성자 매개변수 앞에 `val`이나 `var`가 있는지 확인해야 합니다.

```kotlin
class Hero(
    val name: String,     // 읽을 수 있는 프로퍼티
    val nickname: String, // 읽을 수 있는 프로퍼티
    var hp: Int,          // 읽고 쓸 수 있는 프로퍼티
) {
    fun printInfo() {
        println("$name / $nickname / $hp")
    }
}
```

- `name: String`: 생성자 본문과 `init` 블록에서 사용할 수 있습니다.
- `val nickname: String`: 객체가 만들어진 뒤에도 읽을 수 있습니다.
- `var hp: Int`: 객체가 만들어진 뒤 읽고 쓸 수 있습니다.

`val`이나 `var`가 없는 매개변수는 자동으로 프로퍼티가 되지 않습니다.

### 1-4. `val`과 `var`

```kotlin
class Hero(var hp: Int)

val hero = Hero(100)
hero.hp = 50       // hp가 var이면 가능
// hero = Hero(30)  // val 변수 자체에 다른 객체를 대입할 수 없음
```

- `val`: 참조 자체를 다시 대입할 수 없습니다.
- `var`: 참조 또는 값을 다시 대입할 수 있습니다.

`val`이 객체 내부까지 모두 변경할 수 없다는 뜻은 아닙니다.

```kotlin
class PartyMember(var hp: Int)

val member = PartyMember(100)
member.hp = 50       // member가 가리키는 객체의 프로퍼티는 변경 가능
// member = PartyMember(30) // member 변수 자체를 바꾸는 것은 불가능
```

Java의 `final` 참조 변수와 비슷하게 생각할 수 있지만, `val`이 객체를
깊은 곳까지 불변으로 만드는 것은 아닙니다.

### 1-5. 읽기는 허용하고 쓰기는 막는 `private set`

게임 캐릭터의 HP를 외부 코드가 마음대로 바꾸면 잘못된 상태가 생길 수
있습니다. 예를 들어 전투 규칙을 거치지 않고 HP를 `-999`로 만들 수 있습니다.

```java
public class Hero {
    private int hp = 100;

    public int getHp() {
        return hp;
    }

    public void damage(int amount) {
        hp -= amount;
    }
}
```

Kotlin에서는 getter는 공개로 두고 setter만 숨길 수 있습니다.

```kotlin
class Hero(
    val name: String,
    hp: Int = MAX_HP,
) {
    var hp: Int = hp
        private set

    fun damage(amount: Int) {
        hp = (hp - amount).coerceAtLeast(0)
    }

    fun sleep() {
        hp = MAX_HP
    }

    companion object {
        const val MAX_HP = 100
    }
}
```

사용하는 쪽에서는 HP를 읽을 수 있지만 직접 대입할 수 없습니다.

```kotlin
val hero = Hero("홍길동")
println(hero.hp)  // 가능
hero.damage(30)   // 가능
hero.sleep()      // 가능
// hero.hp = 50   // 컴파일 오류: setter가 private
```

이 코드에서 `hp`의 의미는 다음과 같습니다.

| 코드 | 의미 |
| --- | --- |
| `var hp: Int` | getter와 setter가 있는 프로퍼티 |
| `private set` | setter는 `Hero` 내부에서만 사용 가능 |
| `hero.hp` | 공개 getter를 통한 읽기 |
| `hp = ...` | 클래스 내부에서만 가능한 쓰기 |

`private set`은 캡슐화에서 매우 자주 사용하는 형태입니다. 외부에는 현재
상태를 보여 주되, 상태를 바꾸는 방법은 `damage()`, `sleep()` 같은 의미 있는
메서드로 제한할 수 있습니다.

### 1-6. 사용자 정의 setter와 `field`

setter에서 입력값을 검사하려면 `set(value)`를 작성합니다.

```kotlin
class Hero(
    val name: String,
    initialHp: Int = MAX_HP,
) {
    var hp: Int = initialHp
        set(value) {
            require(value in 0..MAX_HP) {
                "HP는 0부터 $MAX_HP 사이여야 합니다: $value"
            }
            field = value
        }

    companion object {
        const val MAX_HP = 100
    }
}
```

여기서 중요한 단어는 `value`와 `field`입니다.

- `value`: setter로 전달된 새로운 값입니다.
- `field`: 프로퍼티가 실제로 저장하는 backing field입니다.
- `field = value`: 검사를 통과한 값을 실제 저장 공간에 넣습니다.

다음처럼 프로퍼티 이름을 다시 대입하면 setter가 자기 자신을 다시 호출하게
되어 문제가 생길 수 있습니다.

```kotlin
// 잘못된 예
// set(value) { hp = value }

// 올바른 예
set(value) { field = value }
```

Java로 비교하면 다음 코드와 같은 의도입니다.

```java
public void setHp(int hp) {
    if (hp < 0 || hp > MAX_HP) {
        throw new IllegalArgumentException("HP 범위 오류");
    }
    this.hp = hp;
}
```

### 1-7. 사용자 정의 getter와 계산 프로퍼티

현재 상태에서 계산할 수 있는 값은 메서드 대신 읽기 전용 프로퍼티로 표현할
수 있습니다.

```java
public boolean isAlive() {
    return hp > 0;
}
```

```kotlin
val isAlive: Boolean
    get() = hp > 0
```

이 `isAlive`는 값을 따로 저장하지 않고 읽을 때마다 `hp > 0`을 계산합니다.
이런 프로퍼티를 **계산 프로퍼티**라고 볼 수 있습니다.

`field`가 필요한 프로퍼티와 필요하지 않은 프로퍼티를 비교합니다.

```kotlin
var hp: Int = 100
    set(value) {
        field = value // 실제 값을 저장하므로 field 사용
    }

val isAlive: Boolean
    get() = hp > 0   // 계산만 하므로 field 없음
```

### 1-8. 프로퍼티에서 자주 하는 실수

#### 실수 1: `val`을 무조건 상수라고 생각하기

```kotlin
val hero = Hero("홍길동")
hero.damage(10) // 객체 내부 상태 변경은 클래스가 허용하면 가능
```

`val`은 변수에 다른 객체를 다시 넣을 수 없다는 뜻입니다. 객체의 내부
프로퍼티가 `var`인지, 변경 메서드가 공개되어 있는지는 별도로 확인해야 합니다.

#### 실수 2: 프로퍼티를 public으로 열어 두기

```kotlin
class Hero {
    var hp: Int = 100 // 외부에서 어떤 값이든 대입 가능
}
```

규칙을 지켜야 하는 상태라면 다음 중 하나를 선택합니다.

```kotlin
var hp: Int = 100
    private set
```

```kotlin
var hp: Int = 100
    set(value) {
        require(value in 0..100)
        field = value
    }
```

#### 실수 3: 프로퍼티와 필드를 완전히 같은 것으로 생각하기

프로퍼티는 외부에 공개하는 접근 규칙까지 포함한 개념입니다. 항상 실제
저장 공간을 가지는 것은 아닙니다. `isAlive`처럼 계산만 하는 프로퍼티도
있습니다.

## 2. `Cleric`으로 보는 생성자와 메서드

### 2-1. Java의 생성자 오버로드

기존 `Cleric`은 여러 생성자를 제공할 수 있습니다.

```java
public class Cleric {
    private static final int MAX_HP = 50;
    private static final int MAX_MP = 10;

    private String name;
    private int hp;
    private int mp;

    public Cleric(String name) {
        this(name, MAX_HP, MAX_MP);
    }

    public Cleric(String name, int hp) {
        this(name, hp, MAX_MP);
    }

    public Cleric(String name, int hp, int mp) {
        this.name = name;
        this.hp = hp;
        this.mp = mp;
    }
}
```

생성자마다 중복이 생기기 때문에 `this(...)`로 하나의 생성자에 연결합니다.

### 2-2. Kotlin의 기본 인자와 이름 있는 인자

Kotlin에서는 생성자 하나에 기본값을 지정할 수 있습니다.

```kotlin
class Cleric(
    val name: String,
    initialHp: Int = MAX_HP,
    initialMp: Int = MAX_MP,
) {
    var hp: Int = initialHp
        private set

    var mp: Int = initialMp
        private set

    companion object {
        const val MAX_HP = 50
        const val MAX_MP = 10
    }
}
```

호출할 때 필요한 값만 전달할 수 있습니다.

```kotlin
val cleric1 = Cleric("세실")
val cleric2 = Cleric("로사", initialHp = 30)
val cleric3 = Cleric("유나", initialHp = 40, initialMp = 5)
```

이름을 적는 방식을 **이름 있는 인자(named argument)** 라고 합니다. 인자
순서를 헷갈릴 가능성이 줄고, 숫자가 많은 생성자에서 의미가 잘 드러납니다.

### 2-3. `Cleric.selfAid()` 비교

Java의 `if`, 대입, 메서드 반환 구조는 Kotlin에서도 거의 같습니다.

```java
public void selfAid() {
    if (mp < MP_COST) {
        return;
    }

    mp -= MP_COST;
    hp = MAX_HP;
}
```

```kotlin
fun selfAid() {
    if (mp < MP_COST) {
        return
    }

    mp -= MP_COST
    hp = MAX_HP
}
```

차이는 주로 문법입니다.

| Java | Kotlin |
| --- | --- |
| `public void selfAid()` | `fun selfAid()` |
| 반환 타입이 메서드 앞 | 반환 타입이 `: Int`처럼 뒤에 옴 |
| 문장 끝에 `;` | 보통 생략 |
| `this.hp` | 같은 이름 충돌이 없으면 `hp` |

Kotlin의 `Unit`은 Java의 `void`와 비슷하게 반환할 값이 없다는 뜻입니다.
대부분의 경우 반환 타입을 생략하면 `Unit`으로 처리됩니다.

### 2-4. `Cleric.pray()` 비교

Java 코드의 계산 흐름은 그대로 유지하면서 Kotlin 문법으로 바꿉니다.

```java
int pray(int seconds) {
    int bonus = new Random().nextInt(3);
    int recovery = seconds + bonus;
    int maxRecovery = MAX_MP - mp;
    int actualRecovery = Math.min(recovery, maxRecovery);

    mp += actualRecovery;
    return actualRecovery;
}
```

```kotlin
fun pray(seconds: Int): Int {
    require(seconds >= 0) { "기도 시간은 음수일 수 없습니다" }

    val bonus = (0..2).random()
    val recovery = seconds + bonus
    val maxRecovery = MAX_MP - mp
    val actualRecovery = minOf(recovery, maxRecovery)

    mp += actualRecovery
    return actualRecovery
}
```

여기서 새로 만나는 문법은 다음 정도입니다.

- `fun pray(seconds: Int): Int`: 매개변수와 반환 타입을 뒤에 작성합니다.
- `val`: 다시 대입하지 않는 지역 변수에 사용합니다.
- `(0..2).random()`: `0`부터 `2`까지 포함하는 범위에서 값을 뽑습니다.
- `require(...)`: 조건이 거짓이면 `IllegalArgumentException`을 발생시킵니다.
- `minOf(...)`: Java의 `Math.min(...)`과 비슷한 표준 함수입니다.

### 2-5. 완성된 Kotlin `Cleric`

프로퍼티 캡슐화와 기존 Java의 동작을 함께 적용한 예시입니다.

```kotlin
class Cleric(
    val name: String,
    initialHp: Int = MAX_HP,
    initialMp: Int = MAX_MP,
) {
    var hp: Int = initialHp
        private set

    var mp: Int = initialMp
        private set

    init {
        require(initialHp in 0..MAX_HP) {
            "HP는 0부터 $MAX_HP 사이여야 합니다"
        }
        require(initialMp in 0..MAX_MP) {
            "MP는 0부터 $MAX_MP 사이여야 합니다"
        }
    }

    fun selfAid() {
        if (mp < MP_COST) {
            return
        }

        mp -= MP_COST
        hp = MAX_HP
    }

    fun pray(seconds: Int): Int {
        require(seconds >= 0) { "기도 시간은 음수일 수 없습니다" }

        val recovery = seconds + (0..2).random()
        val actualRecovery = minOf(recovery, MAX_MP - mp)
        mp += actualRecovery
        return actualRecovery
    }

    companion object {
        private const val MP_COST = 5
        const val MAX_HP = 50
        const val MAX_MP = 10
    }
}
```

`hp`와 `mp`를 외부에서 직접 바꾸지 못하도록 했지만, `Cleric` 내부의
`selfAid()`와 `pray()`는 값을 변경할 수 있습니다. 이것이 프로퍼티의
접근 범위를 이용한 캡슐화입니다.

## 3. `SuperHero`로 보는 상속과 오버라이드

### 3-1. Java 상속 코드

```java
public class Hero {
    protected String name;

    public Hero(String name) {
        this.name = name;
    }

    public void attack() {
        System.out.println(name + "의 공격");
    }
}

public class SuperHero extends Hero {
    public SuperHero(String name) {
        super(name);
    }

    @Override
    public void attack() {
        super.attack();
        System.out.println("추가 공격");
    }
}
```

### 3-2. Kotlin 상속 코드

```kotlin
open class Hero(
    protected val name: String,
) {
    open fun attack() {
        println("$name의 공격")
    }
}

class SuperHero(name: String) : Hero(name) {
    override fun attack() {
        super.attack()
        println("추가 공격")
    }
}
```

변경점은 코드로 먼저 확인합니다.

| Java | Kotlin |
| --- | --- |
| `extends Hero` | `: Hero(name)` |
| `super(name)` | 부모 생성자 호출을 클래스 선언 뒤에 작성 |
| `@Override` | `override` 키워드 |
| `public class Hero` | `open class Hero` |
| `public void attack()` | `open fun attack()` |

### 3-3. Kotlin 클래스는 기본적으로 상속할 수 없습니다

Java 클래스는 기본적으로 상속할 수 있습니다. Kotlin 클래스와 메서드는
기본적으로 `final`이므로 상속 또는 오버라이드하려면 `open`을 명시합니다.

```kotlin
open class Hero {
    open fun attack() {
    }
}

class SuperHero : Hero() {
    override fun attack() {
    }
}
```

상속을 허용할 의도가 없는 클래스나 메서드는 별도 표시 없이 그대로 두면
됩니다. Kotlin의 기본값이 상속 금지이므로 실수로 동작을 변경하는 일을 줄일
수 있습니다.

### 3-4. 추상 클래스와 인터페이스 비교

Java에서 알고 있는 개념은 Kotlin에서도 이름과 역할이 거의 같습니다.

```java
public abstract class Character {
    public abstract void attack(Slime slime);
}

public interface Attackable {
    void attack(Slime slime);
}
```

```kotlin
abstract class Character {
    abstract fun attack(slime: Slime)
}

interface Attackable {
    fun attack(slime: Slime)
}
```

구현할 때는 다음처럼 작성합니다.

```java
public class Hero extends Character implements Attackable {
    @Override
    public void attack(Slime slime) {
        System.out.println("공격");
    }
}
```

```kotlin
class Hero : Character(), Attackable {
    override fun attack(slime: Slime) {
        println("공격")
    }
}
```

- 클래스 상속과 추상 클래스 구현에는 `()`가 필요합니다.
- 인터페이스 구현에는 보통 `()`를 쓰지 않습니다.
- 여러 인터페이스를 구현할 때는 쉼표로 이어 씁니다.

## 4. Kotlin에서 새로 익힐 핵심 문법

이 절의 개념은 Java에도 비슷한 방법이 있지만, Kotlin에서 문법과 사용
방식이 특히 달라지는 부분입니다.

### 4-1. 타입 추론

오른쪽 값을 보고 타입을 알 수 있으면 타입을 생략할 수 있습니다.

```java
int hp = 100;
String name = "홍길동";
```

```kotlin
val hp: Int = 100
val name: String = "홍길동"

val inferredHp = 100       // Int로 추론
val inferredName = "홍길동" // String으로 추론
```

팀 코드에서는 공개 API나 타입이 중요한 곳에는 타입을 적고, 의미가 분명한
지역 변수에는 타입 추론을 사용할 수 있습니다.

### 4-2. 문자열 템플릿

```java
System.out.println(name + "의 HP: " + hp);
```

```kotlin
println("$name의 HP: $hp")
println("남은 HP: ${hp.coerceAtLeast(0)}")
```

`$변수`는 간단한 값, `${식}`은 계산식이나 메서드 호출을 넣을 때 사용합니다.

### 4-3. `if`는 값을 반환할 수 있습니다

```java
int damage = critical ? 20 : 10;
```

Kotlin에는 삼항 연산자 대신 `if` 자체가 값을 반환합니다.

```kotlin
val damage = if (critical) 20 else 10
```

여러 줄인 경우에도 마지막 줄의 값이 결과가 됩니다.

```kotlin
val message = if (hero.hp > 0) {
    "아직 싸울 수 있습니다"
} else {
    "전투 불능입니다"
}
```

### 4-4. nullable 타입과 null 안전성

Java에서는 대부분의 참조 타입에 `null`을 넣을 수 있고, 실행 중에
`NullPointerException`이 발생할 수 있습니다.

```java
String name = null;
if (name != null) {
    System.out.println(name.length());
}
```

Kotlin은 `null`이 될 수 있는 타입을 타입 이름 뒤에 `?`로 표시합니다.

```kotlin
var nickname: String? = null
```

`String`과 `String?`은 서로 다른 타입입니다.

```kotlin
val name: String = "홍길동"
val nickname: String? = null

// val length = nickname.length // 컴파일 오류
```

nullable 값을 사용하려면 null일 때의 동작을 코드로 표현해야 합니다.

#### 안전 호출 `?.`

```kotlin
val length: Int? = nickname?.length
```

`nickname`이 null이면 `length`를 호출하지 않고 결과도 null이 됩니다.

#### Elvis 연산자 `?:`

```kotlin
val displayName = nickname ?: "이름 없음"
```

왼쪽 값이 null이 아니면 왼쪽 값을 사용하고, null이면 오른쪽 기본값을
사용합니다.

#### null이 아님을 확신하는 `!!`

```kotlin
val length = nickname!!.length
```

`!!`는 null이면 예외를 발생시킵니다. 컴파일 오류를 잠시 없애는 용도로
남용하지 말고, 가능하면 `?.`, `?:`, `if`로 안전한 흐름을 작성합니다.

#### `Cleric` 이름 검증에 적용하기

```java
public void setName(String name) {
    if (name == null) {
        throw new IllegalArgumentException("이름이 null이면 안 됩니다");
    }
    this.name = name;
}
```

Kotlin에서는 애초에 null을 받지 않는 프로퍼티로 선언할 수 있습니다.

```kotlin
class Cleric(val name: String)
```

정말 이름이 없을 수 있는 경우에만 nullable 타입을 사용합니다.

```kotlin
class Cleric(val nickname: String?)
```

### 4-5. 기본 인자와 이름 있는 인자

Java는 생성자 오버로드를 자주 사용합니다.

```java
new Cleric("세실");
new Cleric("로사", 30, 5);
```

Kotlin은 기본 인자와 이름 있는 인자로 같은 의도를 표현합니다.

```kotlin
Cleric("세실")
Cleric("로사", initialHp = 30, initialMp = 5)
```

메서드에도 기본 인자를 사용할 수 있습니다.

```kotlin
fun damage(amount: Int = 10) {
    hp = (hp - amount).coerceAtLeast(0)
}

hero.damage()
hero.damage(amount = 30)
```

### 4-6. `is`와 안전한 타입 변환

Java의 `instanceof`와 캐스트는 다음처럼 바뀝니다.

```java
if (hero instanceof SuperHero) {
    SuperHero superHero = (SuperHero) hero;
    superHero.fly();
}
```

```kotlin
if (hero is SuperHero) {
    hero.fly()
}
```

Kotlin은 `is` 검사를 통과한 뒤 같은 블록 안에서 자동으로 타입을 좁혀
사용할 수 있습니다. 이를 스마트 캐스트라고 합니다.

## 5. 컬렉션은 코드로 비교하기

### Java의 리스트

```java
List<Hero> party = new ArrayList<>();
party.add(new Hero("홍길동"));
party.add(new SuperHero("이순신"));

for (Hero hero : party) {
    hero.attack();
}
```

### Kotlin의 리스트

```kotlin
val party = mutableListOf<Hero>()
party.add(Hero("홍길동"))
party.add(SuperHero("이순신"))

for (hero in party) {
    hero.attack()
}
```

초기값이 정해져 있다면 더 짧게 작성할 수 있습니다.

```kotlin
val party = listOf(
    Hero("홍길동"),
    SuperHero("이순신"),
)
```

| Kotlin 타입 | 의미 |
| --- | --- |
| `List<Hero>` | 읽기 전용으로 사용하는 리스트 인터페이스 |
| `MutableList<Hero>` | 추가, 삭제, 수정이 가능한 리스트 인터페이스 |
| `listOf(...)` | 읽기 전용 리스트를 만드는 함수 |
| `mutableListOf(...)` | 변경 가능한 리스트를 만드는 함수 |

`List`가 언제나 완전한 불변이라는 뜻은 아닙니다. 현재 참조를 통해 수정
메서드를 제공하지 않는다는 의미에 가깝습니다.

### 컬렉션 변환 예시

```java
List<String> names = new ArrayList<>();
for (Hero hero : party) {
    names.add(hero.getName());
}
```

```kotlin
val names = party.map { hero -> hero.name }
```

람다와 `map`은 유용하지만, 첫 수업에서는 문법을 외우기보다 “목록의 각
요소를 다른 값으로 변환한다”는 의미만 확인합니다.

## 6. 5분 미니 연습

다음 Java 메서드를 Kotlin 메서드로 바꿔 보세요.

```java
public void damage(Hero hero, int amount) {
    if (amount <= 0) {
        return;
    }

    int nextHp = hero.getHp() - amount;
    hero.setHp(Math.max(nextHp, 0));
    System.out.println(hero.getName() + "의 HP: " + hero.getHp());
}
```

### 작성 조건

- Kotlin 함수 문법을 사용합니다.
- `hero.getHp()`와 `hero.setHp(...)`를 프로퍼티 문법으로 바꿉니다.
- HP가 0보다 작아지지 않도록 합니다.
- 문자열 템플릿을 사용합니다.
- `amount`가 0 이하이면 아무것도 하지 않습니다.

### 예시 답안

```kotlin
fun damage(hero: Hero, amount: Int) {
    if (amount <= 0) {
        return
    }

    hero.hp = (hero.hp - amount).coerceAtLeast(0)
    println("${hero.name}의 HP: ${hero.hp}")
}
```

만약 `Hero.hp`의 setter를 `private`으로 만들었다면 위 함수에서 직접
대입할 수 없습니다. 그 경우에는 `Hero` 내부에 `damage()` 메서드를 두고,
외부에서는 그 메서드를 호출해야 합니다.

```kotlin
class Hero(
    val name: String,
    hp: Int = MAX_HP,
) {
    var hp: Int = hp
        private set

    fun damage(amount: Int) {
        if (amount > 0) {
            hp = (hp - amount).coerceAtLeast(0)
        }
    }

    companion object {
        const val MAX_HP = 100
    }
}
```

이 차이가 캡슐화의 핵심입니다. 단순히 `getHp()`를 `hp`로 바꾸는 데서
끝나지 않고, 상태 변경 책임을 어디에 둘지 함께 판단해야 합니다.

## 7. Java와 Kotlin 변환 체크리스트

### Java 개념과 Kotlin 문법 대응

| Java | Kotlin |
| --- | --- |
| `class Hero` | `class Hero` |
| `extends Hero` | `: Hero()` |
| `implements Attackable` | `: Attackable` |
| `@Override` | `override` |
| `abstract` | `abstract` |
| `private String name` + getter | `private` 또는 `val name: String` |
| getter/setter 호출 | 프로퍼티 접근 `hero.name` |
| `final` 지역 변수 | `val` |
| 변경 가능한 변수 | `var` |
| `void` | `Unit` 또는 반환 타입 생략 |
| `null` 검사 | nullable 타입과 `?.`, `?:` |
| `instanceof` | `is` |
| 명시적 캐스트 | `as`, 가능한 경우 스마트 캐스트 |
| `List` | `List`, `MutableList` |

### 변환 순서

Java 클래스를 Kotlin으로 옮길 때 다음 순서로 바꿔 보세요.

1. 파일 확장자를 `.java`에서 `.kt`로 생각합니다.
2. `class` 선언과 생성자를 Kotlin 문법으로 옮깁니다.
3. getter/setter가 필요한지 판단하고 프로퍼티로 바꿉니다.
4. 외부에서 직접 변경하면 안 되는 값에는 `private set`을 적용합니다.
5. 메서드의 `fun`, 매개변수 타입, 반환 타입을 정리합니다.
6. `extends`, `implements`, `@Override`를 Kotlin 상속 문법으로 바꿉니다.
7. null이 될 수 있는 값에만 `?`를 붙이고, 사용 지점에서 안전한 처리를 추가합니다.
8. 마지막으로 세미콜론, 타입 추론, 문자열 템플릿을 정리합니다.

## 8. 오늘은 일부러 다루지 않는 것

Kotlin에는 더 많은 편의 기능이 있지만, 첫 1시간에 모두 배우면 Java와
Kotlin의 대응 관계를 놓치기 쉽습니다. 다음 주제로 확장할 수 있습니다.

- `data class`
- 확장 함수
- `let`, `also`, `apply`, `run` 같은 scope function
- 컬렉션의 `filter`, `fold`, `groupBy`
- 코루틴과 `suspend`
- sealed class와 고급 `when`

먼저 오늘 배운 프로퍼티, 캡슐화, 상속, null 안전성을 사용해 기존 과제를
작은 Kotlin 코드로 옮겨 보는 것이 우선입니다.
