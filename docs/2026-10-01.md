# 얕은 복사

    - 바깥 객체만 새로 만들고 안에 있는 내용은 객체의 원본과 공유하는 것,
    - Book을 복사했는데 두 Book이 같은 Date publishDate를 함께 참조한다면 얕은 복사다. 이러한 행위는 복사본의 날짜를 수정했는데 원본의 날짜도 바뀔 수도 있다.
    - 내부 값이 String, int처럼 수정할 수 없는 값이거나, 일부러 데이터를 공유해도 되는 경우에는 얕은 복사도 괜찮다. 다만 Date, List, 배열, 직접 만든 객체처럼 수정 가능한 값이 들어 있으면 조심해야한다.

        - 왜 조심해야해? ai야 도와줘

            -   수정 가능한 객체를 얕게 복사하면 원본과 복사본이 내부 객체 하나를 같이 쓰기 때문이에요.
                예를 들어 원본 책과 복사본 책이 같은 Date 객체를 공유한다고 해볼게요. 복사본의 출간일을 바꾸면, 사실은 둘이 같은 날짜 객체를 보고 있으므로 원본의 출간일도 같이 바뀝니다. “복사했으니 독립적일 것”이라고 생각했는데 예상치 못한 변경이 퍼지는 거죠. 
                String이나 int는 이런 문제가 없어요.
                - int는 값 자체가 복사됩니다.
                - String은 내용을 바꾸는 대신 새 문자열을 만들어 내는 불변 객체입니다.
                반대로 Date, List, 배열, 직접 만든 객체는 내부 내용을 바꿀 수 있어서, 공유 중이라는 사실을 모르고 한쪽만 수정해도 다른 쪽에 영향을 줍니다. 그래서 원본과 복사본을 각각 수정해야 한다면 깊은 복사를 사용합니다.

# 깊은 복사

    — 내부 객체까지 독립적으로 만드는 복사 기능
    - 깊은 복사는 바깥 객체뿐 아니라 내부의 수정 가능한 객체도 새로 만든다.
    - Book 복사본의 publishDate에 새 Date를 넣은 이유가 이거다. 이러한 행위는 복사본 날짜를 바꿔도 원본 날짜에는 영향이 없게 된다.
