## 1. 배운 점

### DataSource란 무엇일까요? ###
- 비유하자면: 우리가 인터넷 쇼핑으로 물건을 살 때, 물건이 어떻게 만들어졌고 택배 트럭이 어떤 도로를 거쳐서 
  우리 집까지 왔는지 일일이 알 필요가 없죠? 
  그냥 현관 앞에 놓인 택배 상자(인터페이스)만 뜯어서 안에든 물건을 쓰면 됩니다.

- 프로그래밍에서의 뜻: 파일에서 글자를 읽어오거나, 인터넷(네트워크)에서 데이터를 가져오거나, 
  데이터베이스에 저장하는 복잡하고 지저분한 기술 코드들을 '데이터 소스'라는 껍데기(인터페이스) 
  안에 꽁꽁 숨겨두는(캡슐화) 기술이에요.

- 왜 쓸까요? 이렇게 하면 나중에 데이터를 저장하는 방식을 파일에서 
  인터넷(서버)으로 바꾸더라도, 메인 프로그램 코드는 단 한 줄도 고칠 필요가 없어져서 유지보수가 천국처럼 편해집니다!

#### 회고.
- UI나 비즈니스 로직 코드 안에 파일 입출력(File.readText())이나 JSON 파싱 코드가 뒤엉켜 있으면 나중에 코드를 
  고치기 힘들다는 점을 절감하고, 이를 깔끔하게 분리하는 캡슐화의 강력함.

- TodoDataSource나 StockDataSource처럼 외부와 소통하는 인터페이스를 먼저 정의함으로써, 내부 구현 방식
  (파일, DB, 네트워크 등)이 어떻게 바뀌든 메인 코드는 전혀 흔들리지 않는 유연한 구조.
 
- 단순한 문법 공부를 넘어, 대규모 앱이나 서비스 개발 시 왜 레이어를 나누고 DataSource 패턴을 적용해야 하는지 
  그 설계 철학을 명확히 이해.
