# 프롬프트

피그마링크에서 Design페이지를 검토해서 다음 기능 마크다운파일 뽑아줘

- UI에 표시되는 정보들을 기반으로 필요한 도메인 객체를 도출하시오
- 모델 클래스의 속성을 도출하시오
- 각 도메인 객체에 대한 Repository 인터페이스를 설계하시오
- Repository의 책임과 역할을 명확히 하여 필요한 메서드들을 도출하시오

레시피 앱 Figma를 분석하여 다음을 도출 (코드 작성 X)
1. 단순 조회라 Repository 직통으로 충분한 기능 1~2개
2. 비즈니스 규칙(판정/가공) 함수가 필요한 기능 2~3개
3. 각 기능의 블랙박스 스펙 정의:
   • 필요한 부품: 어떤 Repository(들)가 필요한가?
   • 입력값: 실행에 필요한 매개변수는 무엇인가?
   • 결과물 (Result): 성공 데이터 & 실패 규칙 에러(Enum)

AI가 작성한 설계를 그대로 믿지 말고 비판적으로 검토
1. 과잉 설계 걷어내기 (불필요한 함수 분리 제거)
	• 단순 CRUD 조회는 화면(UI) → Repository 직통으로 간소화
  
2. 비즈니스 규칙 누락 확인 (규칙 실패 정의)
	• 입력값 검증, 최대 개수 제한, 권한 등 비즈니스 정책 누락 여부
	• NetworkError(데이터 실패) 외에 규칙 실패 Result 정의 여부

3. 단일 책임 원칙(SRP) 점검
	• Repository에 비즈니스 판정 코드가 섞여 들어가지 않았는가?
