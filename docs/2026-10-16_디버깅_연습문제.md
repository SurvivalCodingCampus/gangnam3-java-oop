## 1. 연습문제 1 : JSON 데이터를 담을 클래스

> 파일에서 json 데이터를 읽어서 처리해야 한다. 이 데이터를 담을 수 있는 클래스를 작성하시오.
> 파일은 아래 링크에서 내려받아 파일 조작을 통해 읽어와서 활용할 것
> https://gist.github.com/junsuk5/71eb1eadc17978492a83e8593fe5c9f0

### 1-1. 파일 준비

1. 링크를 열고 `../src/main/resources/chart_data.json` 오른쪽 위의 **Raw** 를 누른다.
2. 열린 페이지에서 ⌘S (Win: Ctrl+S) 로 저장한다. 이름은 `../src/main/resources/chart_data.json`.
3. 저장한 파일을 프로젝트 맨 위 폴더 (`gangnam3-java-oop/`)에 넣는다. 그래야 `File("chart_data.json")` 으로 찾을 수 있다.
    - 연습용 데이터다. 커밋하지 않는다.

### 1-2. JSON 모양 살펴보기

```json
{
  "collectionChartDataList": [
    {
      "collectionName": "collection1",
      "collectionSalePrice": [
        {
          "price": 58.25,
          "cvtDatetime": "2023-03-26T08:00:00"
        },
        {
          "price": 58.50,
          "cvtDatetime": "2023-03-26T08:00:10"
        }
      ]
    },
    ...
    {
      "collectionName": "collection68"
    },
    ...
  ]
}
```

| 단계                      | JSON                                       | 뜻               | Kotlin 타입                  |
|---------------------------|--------------------------------------------|------------------|------------------------------|
| 맨 바깥 `{ }`             | `collectionChartDataList` 하나를 가진 객체 | 전체 차트 데이터 | `ChartData` 클래스           |
| `collectionChartDataList` | `[ ... ]` 리스트, 75개                     | 컬렉션 목록      | `List<CollectionChartData>`  |
| 리스트 안의 `{ }`         | `collectionName`, `collectionSalePrice`    | 컬렉션 하나      | `CollectionChartData` 클래스 |
| `collectionName`          | `"collection1"`                            | 이름             | `String`                     |
| `collectionSalePrice`     | `[ ... ]` 리스트                           | 가격 기록 목록   | `List<CollectionSalePrice>`  |
| 가격 기록 `{ }`           | `price`, `cvtDatetime`                     | 기록 하나        | `CollectionSalePrice` 클래스 |
| `price`                   | `58.25` (소수)                             | 가격             | `Double`                     |
| `cvtDatetime`             | `"2023-03-26T08:00:00"` (따옴표)           | 날짜·시간 글자   | `String`                     |

- 규칙 : `{ }` 하나마다 클래스 하나, `[ ]` 는 `List<...>`, 필드 이름은 JSON 키와 **똑같이** 쓴다. (직렬화 슬라이드 11쪽 "Json 과 동일한 필드명인 경우,
  @Serializable 어노테이션만 붙이면 준비 끝")
- **함정 : 75개 중 `collection68` 하나에는 `collectionSalePrice` 가 아예 없다.** (68번째, 리스트 번호로는 67)

### 1-3. 만드는 순서

**1단계. 가장 안쪽 `{ }` 부터 클래스로 만든다.**

```kotlin
@Serializable
data class CollectionSalePrice(
    val price: Double,
    val cvtDatetime: String
)
```

**2단계. 그것을 담는 컬렉션 클래스를 만든다. `collectionSalePrice` 는 없을 수도 있게 한다.**

```kotlin
@Serializable
data class CollectionChartData(
    val collectionName: String,
    val collectionSalePrice: List<CollectionSalePrice>? = null
)
```

- `?` : 값이 `null` 일 수 있다.
- `= null` : **JSON 에 이 키가 없으면** `null` 을 넣는다. 직렬화 라이브러리는 기본값이 있는 필드만 "없어도 된다" 고 본다.
- `?` 만 붙이고 `= null` 을 빼면, `collection68` 에서 똑같이 에러가 난다. (1-5 참고)

**3단계. 맨 바깥 클래스를 만든다.**

```kotlin
@Serializable
data class ChartData(
    val collectionChartDataList: List<CollectionChartData>
)
```

**4단계. 파일을 읽어서 역직렬화한다. (파일 조작 4쪽 + 직렬화 12쪽)**

```kotlin
    val file: File = File("chart_data.json")
val text: String = file.readText()

val chartData: ChartData = Json.decodeFromString<ChartData>(text)
```

### 1-4. 완성 코드

```kotlin
// 디버깅 연습문제 1 : JSON 데이터를 담을 클래스
// [단축키] Serializable, Json, File 이 빨간색이면 그 위에서 ⌥Enter (Win: Alt+Enter) → Import

package com.survivalcoding.day15

import kotlinx.serialization.Serializable
import kotlinx.serialization.json.Json
import java.io.File

// 맨 바깥 { } : 컬렉션 목록을 가진다
@Serializable
data class ChartData(
    val collectionChartDataList: List<CollectionChartData>
)

// 컬렉션 하나. collectionSalePrice 가 없는 컬렉션(collection68)도 있어서 ? = null
@Serializable
data class CollectionChartData(
    val collectionName: String,
    val collectionSalePrice: List<CollectionSalePrice>? = null
)

// 가격 기록 하나
@Serializable
data class CollectionSalePrice(
    val price: Double,
    val cvtDatetime: String
)

// [단축키] main 입력 후 Tab → fun main() { } 가 만들어진다
fun main() {
    // 1. 파일을 읽는다 (파일 조작 4쪽)
    val file: File = File("chart_data.json")
    val text: String = file.readText()

    // 2. JSON → 객체 (직렬화 12쪽)
    // [단축키] 이 줄에 브레이크포인트 ⌘F8 (Win: Ctrl+F8) → Debug 로 실행 → F8 한 번 → Variables 에서 chartData 를 펼쳐 본다
    val chartData: ChartData = Json.decodeFromString<ChartData>(text)

    // 3. 잘 들어왔는지 확인한다 (로깅, 슬라이드 4·5쪽)
    println(chartData.collectionChartDataList.size)
    println(chartData.collectionChartDataList[0])
    println(chartData.collectionChartDataList[67])
}
// [단축키] 실행 : fun main 왼쪽 초록 ▶ 클릭, 또는 ⌃⇧R (Win: Ctrl+Shift+F10)
```

### 1-5. 실행 결과

```
75
CollectionChartData(collectionName=collection1, collectionSalePrice=[CollectionSalePrice(price=58.25, cvtDatetime=2023-03-26T08:00:00), CollectionSalePrice(price=58.5, cvtDatetime=2023-03-26T08:00:10)])
CollectionChartData(collectionName=collection68, collectionSalePrice=null)
```

- 75개가 모두 들어왔다.
- `collection68` 은 `collectionSalePrice=null` 이다. 에러 없이 처리됐다.
- `58.50` 이 `58.5` 로 보이는 것은 Double 이 끝의 0 을 빼고 보여 주기 때문이다. 값은 같다.

### 1-6. 디버깅 연습 : `? = null` 을 빼면

```kotlin
    val collectionSalePrice: List<CollectionSalePrice>        // ? = null 없음
```

실행하면 이 에러가 난다.

```
Exception in thread "main" kotlinx.serialization.MissingFieldException: Field 'collectionSalePrice' is required for type with serial name 'com.survivalcoding.day15.CollectionChartData', but it was missing at path: $.collectionChartDataList[67]
```

에러 메시지 읽기

| 부분                                                        | 뜻                                        |
|-------------------------------------------------------------|-------------------------------------------|
| `MissingFieldException`                                     | 필드가 없다는 예외                        |
| `Field 'collectionSalePrice' is required`                   | `collectionSalePrice` 는 꼭 있어야 하는데 |
| `but it was missing at path: $.collectionChartDataList[67]` | 리스트의 67 번(68번째) 에 없었다          |

- `$.collectionChartDataList[67]` 가 **어디서** 났는지 알려 준다. 그 위치를 JSON 에서 찾으면 `collection68` 이다.
- 그래서 그 필드를 "없어도 되는" 필드로 바꾼다 → `? = null`
- `?` 만 붙여도 같은 에러가 난다. `null` 을 받을 수는 있지만, 키 자체가 없을 때 무엇을 넣을지 (기본값)가 없기 때문이다.

### 2-2. 증상 : 언제 실행해도 결과가 이상하다

### 2-3. 버그 찾기 (슬라이드의 방법대로)

**버그 1 : 월이 이상하다 → 로깅 / Evaluate 로 `month` 확인**

```kotlin
            val month = nowDate.substring(5, 7)
            println(month)      // 로깅 (슬라이드 4·5쪽) : 37, 40 같은 값이 나온다
```

또는 `val month` 줄에 브레이크포인트 (⌘F8) → Debug → F8 → Variables 에서 `nowDate` 와 `month` 를 본다.

- `nowDate` 가 `2026-40-16` 처럼 나온다. 가운데가 월이 아니다.
- 원인 : 8번째 줄의 날짜 패턴 `"yyyy-mm-dd"`

| 패턴 글자     | 뜻             |
|---------------|----------------|
| `MM` (대문자) | 월 (01~12)     |
| `mm` (소문자) | **분** (00~59) |

- 그래서 `month` 에 분이 들어간다. 40 분이면 `"40"` → `when` 의 어느 것에도 안 맞아서 `else -> nowTime` → `갑자1국`.
- 분이 01~12 일 때 실행하면 우연히 `경오N국` 이 나와서, 가끔은 맞아 보인다. 이런 버그는 잡기 어렵다.

**버그 2 : 몇 시든 갑자1국 → 브레이크포인트로 `when` 확인**

`when {` 줄에 브레이크포인트 → Debug → F8 로 한 줄씩 → 첫 번째 줄에서 바로 `return` 된다.

```kotlin
            nowTime.hour >= 0 || nowTime.hour < 2 -> return timeDataOne.first().ty1
```

- `||` 는 "또는" 이다. 둘 중 하나만 참이어도 참이다.
- `nowTime.hour >= 0` 은 시각이 몇 시든 **항상 참**. 그래서 첫 줄에서 언제나 `ty1` 을 돌려준다.
- "0시 이상 **그리고** 2시 미만" 이어야 하므로 `&&` 를 써야 한다.

| 연산자 | 뜻     | `hour = 17` 일 때 `hour >= 0 ? hour < 2` |
|--------|--------|------------------------------------------|
| `\|\|` | 또는   | `true \|\| false` → **true** (틀림)      |
| `&&`   | 그리고 | `true && false` → **false** (맞음)       |

**버그 3 : 빠진 시간대 → 표로 정리해 보기 (작게 시작, 슬라이드 9쪽)**

`||` 를 `&&` 로만 바꾸고 각 줄의 범위를 적어 보면

| 원래 코드의 범위   | 돌려주는 값                     |
|--------------------|---------------------------------|
| 0~2시              | ty1                             |
| **2~4시 : 없음**   | (마지막 `return result` → ty12) |
| 4~6시              | ty2                             |
| 6~8시              | ty3                             |
| 8~10시             | ty4                             |
| 10~12시            | ty5                             |
| 12~14시            | ty6                             |
| **14~16시 : 없음** | (마지막 `return result` → ty12) |
| 16~18시            | ty7                             |
| 18~20시            | ty8                             |
| 20~22시            | ty9                             |
| 22~24시            | ty10                            |

- 2~4시, 14~16시 두 구간이 빠졌다.
- `ty11` 은 어디에서도 쓰이지 않는다.
- 하루 24시간을 2시간씩 나누면 12칸, 값도 `ty1` ~ `ty12` 12개다. 그래서 순서대로 짝짓는 것이 의도로 보인다. [추정]
    - 0~2시 ty1, 2~4시 ty2, 4 ~6시 ty3 … 22~24시 ty12

### 2-6. fork → 수정 → PR 순서 (직접 한다)

1. https://github.com/SurvivalCodingCampus/kotlin-debug-sample 에서 오른쪽 위 **Fork** → Create fork
2. 내 포크를 클론한다 (`~/dev` 에서)

```bash
git clone https://github.com/chungwoncho/kotlin-debug-sample.git
```

3. IntelliJ 에서 `kotlin-debug-sample` 폴더를 연다 (File → Open). Gradle 이 처음에 JDK 17 을 자동으로 내려받느라 시간이 걸릴 수 있다.
   (`jvmToolchain(17)` 이 있어서)
4. 브랜치를 만든다 (영어 이름)

```bash
git switch -c fix/yukym-bugs
```

5. `src/main/kotlin/YukymController.kt` 를 2-4 처럼 고치고, `Main.kt` 를 실행해서 2-5 처럼 나오는지 확인한다.
6. 커밋하고 푸시한다

```bash
git commit -am "fix: 날짜 패턴(MM)과 시간대 조건(&&) 버그 수정"
```

```bash
git push -u origin fix/yukym-bugs
```

7. GitHub 에서 PR 을 만든다
    - base repository : `SurvivalCodingCampus/kotlin-debug-sample`, base : `master`
    - head repository : `chungwoncho/kotlin-debug-sample`, compare : `fix/yukym-bugs`
    - 본문에 찾은 버그 3개 (2-3 의 표)와 고치기 전/후 결과를 적는다.
