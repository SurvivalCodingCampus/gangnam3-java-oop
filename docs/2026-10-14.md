# 예외 / 파일 조작 / 데이터 형식

## 용어 정리

- `예외`: 프로그램이 실행되는 도중에 발생하는 예상치 못한 비정상적인 상황이나 오류
- `파일 조작`: 컴퓨터 시스템에서 파일을 생성, 읽기, 쓰기, 수정, 삭제, 이동 및 복사하는 모든 처리 과정
- `CSV`: 데이터를 `콤마(,)` 로 나눈 형식
- `XML`: `<>` 태그를 활용한 기술 방식. 포함 관계를 기술할 수 있다.
- `JSON`:`속성-값` 쌍이나 `배열` 로 이루어진 데이터를 전달하기 위해 텍스트를 사용하는 데이터 형식. `XML` 에 비해 용량이 적으며, 네트워크 통신에서 가장 많이 사용되고 있다.
- `직렬화`: 객체나 데이터 구조를 연속된 바이트 형태나 `텍스트(JSON, XML 등)` 로 변환하는 과정
- `역직렬화`: `직렬화` 된 데이터를 다시 원래의 객체로 되돌리는 과정

## 클래스 작성 테스트 코드

```kotlin
@DisplayName("toInt 예외 처리 테스트")
class ToIntTest {

    @Test
    fun `정수 형식의 문자열은 toInt로 변환된다`() {
        // given
        val numString = "10"

        // when
        val num = numString.toInt()

        // then
        assertEquals(10, num)
    }

    @Test
    fun `정수 형식이 아닌 문자열을 toInt하면 NumberFormatException 예외를 던진다`() {
        // given
        val numString = "10.5"

        // when & then
        assertThrows(NumberFormatException::class.java) {
            numString.toInt()
        }
    }

    @Test
    fun `try-catch로 NumberFormatException을 처리하면 기본값 0을 반환한다`() {
        // given
        val numString = "10.5"

        // when
        val num: Int = try {
            numString.toInt()
        } catch (e: NumberFormatException) {
            0
        }

        // then
        assertEquals(0, num)
    }

    @Test
    fun `try-catch에서 예외가 발생하지 않으면 변환된 값을 반환한다`() {
        // given
        val numString = "10"

        // when
        val num: Int = try {
            numString.toInt()
        } catch (e: NumberFormatException) {
            0
        }

        // then
        assertEquals(10, num)
    }

    @Test
    fun `toIntOrNull은 변환에 실패하면 null을 반환하고 엘비스 연산자로 기본값을 지정할 수 있다`() {
        // given
        val numString = "10.5"

        // when
        val nullable = numString.toIntOrNull()
        val num = numString.toIntOrNull() ?: 0

        // then
        assertNull(nullable)
        assertEquals(0, num)
    }

    @Test
    fun `runCatching은 변환에 실패하면 getOrDefault로 기본값을 반환한다`() {
        // given
        val numString = "10.5"

        // when
        val num = numString.runCatching { toInt() }.getOrDefault(0)

        // then
        assertEquals(0, num)
    }

    @Test
    fun `runCatching은 변환에 실패하면 NumberFormatException을 담은 실패 결과를 반환한다`() {
        // given
        val numString = "10.5"

        // when
        val result = numString.runCatching { toInt() }

        // then
        assertTrue(result.isFailure)
        assertInstanceOf(NumberFormatException::class.java, result.exceptionOrNull())
    }
}
```

```kotlin
@DisplayName("DefaultFileOperations 클래스 테스트")
class DefaultFileOperationsTest {

    private lateinit var fileOperations: FileOperations
    private lateinit var source: File
    private lateinit var destination: File

    @BeforeEach
    fun setUp() {
        fileOperations = DefaultFileOperations()
        source = File("test_source.txt")
        destination = File("test_destination.txt")
    }

    @AfterEach
    fun tearDown() {
        source.delete()
        destination.delete()
    }

    @Test
    fun `copyFile을 하면 원본 파일의 내용이 대상 파일로 복사된다`() {
        // given
        source.writeText("Hello, world!")

        // when
        fileOperations.copyFile(source, destination)

        // then
        assertTrue(destination.exists())
        assertEquals("Hello, world!", destination.readText())
    }

    @Test
    fun `copyFile을 하면 대상 파일의 기존 내용을 덮어쓴다`() {
        // given
        source.writeText("새로운 내용")
        destination.writeText("기존 내용")

        // when
        fileOperations.copyFile(source, destination)

        // then
        assertEquals("새로운 내용", destination.readText())
    }

    @Test
    fun `copyFile을 해도 원본 파일의 내용은 변하지 않는다`() {
        // given
        source.writeText("Hello, world!")

        // when
        fileOperations.copyFile(source, destination)

        // then
        assertEquals("Hello, world!", source.readText())
    }

    @Test
    fun `빈 파일을 copyFile하면 빈 대상 파일이 생성된다`() {
        // given
        source.writeText("")

        // when
        fileOperations.copyFile(source, destination)

        // then
        assertTrue(destination.exists())
        assertEquals("", destination.readText())
    }

    @Test
    fun `존재하지 않는 원본 파일을 copyFile하면 FileNotFoundException 예외를 던진다`() {
        // given
        val unknown = File("unknown.txt")

        // when & then
        assertThrows(FileNotFoundException::class.java) {
            fileOperations.copyFile(unknown, destination)
        }
    }

    @Test
    fun `존재하지 않는 원본 파일을 copyFile하면 대상 파일은 생성되지 않는다`() {
        // given
        val unknown = File("unknown.txt")

        // when
        runCatching { fileOperations.copyFile(unknown, destination) }

        // then
        assertFalse(destination.exists())
    }
}
```

```kotlin
@DisplayName("Department 직렬화 테스트")
class DepartmentTest {

    private lateinit var department: Department
    private lateinit var file: File

    @BeforeEach
    fun setUp() {
        department = Department("총무부", Employee("홍길동", 41))
        file = File("test_company.json")
    }

    @AfterEach
    fun tearDown() {
        file.delete()
    }

    @Test
    fun `Department를 직렬화하면 leader가 중첩된 JSON 문자열이 된다`() {
        // when
        val json = Json.encodeToString(department)

        // then
        assertEquals("""{"name":"총무부","leader":{"name":"홍길동","age":41}}""", json)
    }

    @Test
    fun `JSON 문자열을 역직렬화하면 Department 객체가 된다`() {
        // given
        val json = """{"name":"총무부","leader":{"name":"홍길동","age":41}}"""

        // when
        val result = Json.decodeFromString<Department>(json)

        // then
        assertEquals("총무부", result.name)
        assertEquals("홍길동", result.leader.name)
        assertEquals(41, result.leader.age)
    }

    @Test
    fun `직렬화한 뒤 다시 역직렬화하면 원래 객체와 같다`() {
        // when
        val json = Json.encodeToString(department)
        val result = Json.decodeFromString<Department>(json)

        // then
        assertEquals(department, result)
    }

    @Test
    fun `직렬화한 JSON을 파일에 쓰고 다시 읽어 역직렬화하면 원래 객체와 같다`() {
        // given
        val json = Json.encodeToString(department)

        // when
        file.writeText(json)
        val result = Json.decodeFromString<Department>(file.readText())

        // then
        assertTrue(file.exists())
        assertEquals(department, result)
    }
}
```

## 정리

- `예외(Exception)`
  - 프로그램을 설계할 때 실행 시에 `예외` 상황이 발생할 가능성이 있는 것을 예측하여, 사전에 `예외 처리` 가 되도록 할 필요가 있다.
  - 이럴 때 적절한 조치가 없으면 프로그램은 에러가 발생하며, 예상 외의 상황에 적절한 조치를 취해야 한다.
  - `예외 처리` 를 할 때는 `실행 시 에러(runtime error)` 를 대처한다.

- `에러의 종류와 대응책`
  - `문법 에러(syntax error)`: 코드의 형식적 오류로써 컴파일 시 에러가 발생한다. 컴파일러의 지적을 보고 수정한다.
  - `실행 시 에러(runtime error)`: 실행 중에 예상 외의 사태가 발생하여 동작이 중지된다. 실행하면 도중에 강제 종료된다. 에러 메시지를 보고 수정한다.
  - `논리 에러(logic error)`: 기술한 처리 내용에 논리적인 오류가 있다. 실행하면 예상 외의 값이 나온다. 원인을 스스로 찾아서 해결해야 한다.

- `예외적인 상황들`
  - `메모리 부족` `파일 찾기 실패` `네트워크 통신 불가` 등이 있다.
  - `try-catch` 문으로 `Exception` 계열 예외를 처리할 수 있다. `try` 블록 내 예외가 발생했을 때 `catch` 블록에서 처리가 옮겨진다. `finally` 블록에서 항상 해야하는 처리를 수행할 수 있다.
  - `throw` 로 에러 처리를 위임하거나 미룰 수 있다.

- `파일 조작의 기본 순서`
  - 파일을 연다
  - 파일을 읽거나 쓴다
  - 파일을 닫는다

- `컴퓨터 세계에서의 직렬화`
  - 데이터 구조나 객체 상태를 저장하고 나중에 재구성할 수 있는 포맷으로 변환하는 과정이다.
  - 객체를 파일의 형태 등으로 저장하거나, 통신하기 쉬운 포맷으로 변환하는 과정을 의미한다.
  - 클래스 내부의 필드에 다른 클래스가 있다면 모두 `직렬화` 처리를 해야 한다.
  - 바이너리(이진 데이터) `직렬화`뿐 아니라, 현대 개발에서는 사람이 읽을 수 있는 텍스트 포맷(JSON)으로 변환하는 것도 `직렬화` 의 범주이다.
