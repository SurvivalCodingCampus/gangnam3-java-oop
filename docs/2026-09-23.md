### 상속

## 서론

# 내가 이해한 상속의 정의
    - 인간이 반복하는 복사 붙여넣기와 같은 행위는 오류가 발생할 수 있다. 그렇기에 더욱 코드의 안전화를 위해 상위 클래스의 내용들을 상속하는 것이 효과적이고 안전하다.

# 상속의 중요성
    - 동어반복을 싫어하는 컴퓨터의 특성상 동일한 문자구조를 반복시키는 것은 연산의 낭비다. 그렇기에 컴퓨터 설계자들은 동어반복적 행위를 예방하기 위해 상속이라는 개념 사용한다. 상속은 부모와 자식의 관계와 같이 유전적 특성을 지니고 있는데 이는 상위의 개념이 하위의 개념이 동일한 작업을 진행할 수 있도록 허락하는 개념으로 이해될 수 있다. 그렇기에 상위 개념은 더욱 추상적으로 표현될 수 있다. 전자 사전이 사전으로 사전이 책으로와 같이 특정성이 점점 흐려지는 것이 가장 효과적이기 때문이다. 해당 이해 아래에서 책은 사전으로, 동화책으로도 나아갈 수 있기 때문이다. 만약 그러하다면 동어반복적인 코드 낭비를 최소화 할 수 있음으로 이해될 수 있다.

# is a 원칙
    - 상속은 이게 말이 되는 것인가? 에 대한 이야기다. 그렇기에 나는 너다. 와 같은 방식이 아닌 나는 사람이다. 와 같은 동일 맥락 상에서 더욱 상위 개념적으로 이해될 수 있다.

# 오버드라이브
    - 상속 가운데 수정을 원하는 내용들이 있다면 그것을 위해 우리가 하는 행위가 바로 상속-오버드라이브다. 이는 기존에 존재하는 메소드를 다시 사용하는 행위다.


## 본론

# 내가 느낀 상속시 중요했던 부분
    - 상속은 있는 것만 가져오는 거다.

public class Slime {
    private String name;
    private int hp;


먼저 부모 클래스인 슬라임에 이렇게만 작성한 다음 나는
   
public class PoisonSlime extends Slime {
    private int poisonCount = 5;

    public PoisonSlime(String name, int hp) {
        super(name, hp);
    }

를 작업했으나 super(name, hp); 에서 빨간불이 나오는 점에서 생각에 잠겼다.
그러나 상속의 개념을 조금 더 이해했더라면 해당 어려움은 쉽게 돌파했을 것이라 판단한다.
먼저 상속은 이전 클래스의 무언가를 사용하는 행위다. 슬라임이 가지고 있던 super(name, hp); 를 내가 입력을 깜빡했던 것이었다. 그렇기에 해당 작업은

public class Slime {
    private String name;
    private int hp;

    public Slime(String name, int hp) {
        this.name = name;
        this.hp = hp;
    }

를 통해 현재 슬라임의 이름과 체력을 가져오는 작업으로 해당 어려움을 극복했다. 

# 내가 느낀분 상속시 중요했던 부분 2
    - getter와 setter의 사이

    int poisonDamage = hero.getHp() / 5;
            hero.setHp(hero.getHp() - poisonDamage);

해당 코드를 나의 언어로 풀면 아래와 같다.

    포이즌 슬라임의 독 데미지는 현재 히어로에게 가져온 hp / 5다
            히어로 hp 수정하겠다. 지금부터 수정한 히어로의 hp는 현재 히어로에게 가져온 hp 에서 독 데미지를 포함한 값이다.

    나는 여기서 get을 현재라는 시간적 표현을 사용하는 것이 조금 더 가시적이라고 생각한다. 이 get은 this. 과는 다른 것으로 이해 된다.
    this. 은 "이제부터 너는~" 이라는 의미로 이해되고 get은 "지금까지의 ~는" 으로 이해했다.


## 결론

# 반복성을 최대한 줄여라!
    - 내가 이해한 상속은 동어반복적 코드를 줄이는 것에 있다. 이것은 비가시적이고 비효율적이다. 다양한 이야기들이 교차되는 컴퓨터 세상에서 가시적이지 않으며 연산에 효율적이지 않은 모든 행동들은 철저하게 절제되어야 한다. 그 과정이 상속이라 나는 생각한다.

# 유사성
    - 코드에는 유사성이 있는 느낌이 든다. 이 유사성은 최대한 현실 세계의 문법에 가깝다고도 느낀다. 그렇기에 컴퓨터 세계의 문법에 익숙해지면 삶이 조금은 더 효과적이라고도 느끼는 하루가 됐다.
