### 캡슐화

## 서론

# 데이터의 저장과 비변경의 중요성
    - 클래스 내부에 저장된 정보들을 다른 메소드를 통해 변경됐을때 그 모든 책임은 클래스의 보안문제에게 있다. 이것은 클래스의 성질이 외부가 열람할 수 있는 정보라는 것에 있다.
      클래스는 외부에서 자신을 열람하고 사용할 수 있도록 만든 존재인데 이는 곧 외부에서 클래스가 가진 정보를 수정하는 행위를 허락한다는 의미를 또한 가지고 있다.
      그렇기에 클래스에게는 외부에서 열람할 수 있는 정보를 억제해야하는 기능이 필수적이다. 이것이 캡슐화다.

# 캡슐화 
    - 캡슐화는 사람이 코딩하는 도중에 발생할 수 있는 실수들을 억제하는 요소라고 보면 편하다. 이는 실수들을 통제하고 또 외부에서 받을 필요 없는 값을
      스스로 차단함으로써 오류를 사전예방하는 행위다.


## 본론

# 오늘 내가 배운 내용
    - 오늘은 캡슐화에 대한 지식을 배웠으며 해당 캡슐화 기능들이 어떻게 작동하는지에 대해 배웠다. 지금부터 내가 중요하다고 이해했으며 복습을 진행하고자 하는 내용들을 아래에 적도록하겠다.

# 클래스 해부도
    - 해당 본문은 필자가 더 나은 이해를 위해 필자가 작성한 위자드 클래스르 해부화한 내용이다.



public class Wizard { // Wizard라는 설계도(클래스) 시작

    // ===== 필드(field): Wizard 객체가 기억할 데이터 =====

    private int hp; // 필드: 체력
                    // private: Wizard 밖에서는 직접 접근 불가

    private int mp; // 필드: 마나

    private Wand wand; // 객체 필드: Wand 타입의 지팡이 객체를 저장하는 자리
                       // 처음에는 값이 없으므로 null 상태

    private String name; // 필드: 마법사의 이름



    // ===== getter: 필드 값을 읽어 가는 메서드 =====

    public String getName() { // name을 읽어 가도록 허용하는 getter
        return name; // Wizard 안에 저장된 name을 돌려줌
    }


    // ===== setter: 필드 값을 안전하게 변경하는 메서드 =====

    public void setName(String name) { // 외부에서 이름 변경을 요청하는 setter
                                       // 괄호 안 String name은 전달받은 새 이름

        if (name == null) { // 새 이름이 null인지 검사
            throw new IllegalArgumentException("이름을 입력하세요.");
            // 잘못된 값이면 오류를 발생시키고 메서드를 중단
        }

        this.name = name;
        // this.name: Wizard 객체가 가지고 있던 필드 name
        // 오른쪽 name: setName()이 전달받은 새 이름
    }


    public int getHp() { // hp 값을 읽어 가도록 허용하는 getter
        return hp; // Wizard 안의 hp 필드 값을 반환
    }


    public void setHp(int hp) { // 체력 변경을 요청하는 setter
        this.hp = hp; // 일단 전달받은 hp를 Wizard의 hp 필드에 저장

        if (hp <= 0) { // 전달받은 hp가 0 이하라면
            this.hp = 0; // 체력이 음수가 되지 않도록 0으로 수정
        }
    }


    public Wand getWand() { // wand 필드의 값을 읽어 가는 getter
        return wand; // Wand 객체를 반환
    }


    public void setWand(Wand wand) { // Wand 객체를 장착하는 setter
        if (wand == null) { // 전달받은 Wand 객체가 없는지 검사
            throw new IllegalArgumentException("무기를 장착하지 않았습니다.");
        }

        this.wand = wand;
        // this.wand: Wizard가 가지고 있는 지팡이 필드
        // 오른쪽 wand: setWand()로 전달받은 지팡이 객체
    }


    public int getMp() { // mp 값을 읽어 가는 getter
        return mp;
    }


    public void setMp(int mp) { // 마나 변경을 요청하는 setter
        if (mp <= 0) { // 마나가 0 이하인지 검사
            System.out.println("마나가 진짜로 부족합니다.");
            throw new IllegalArgumentException("마나가 부족하여 스킬이 중단됩니다.");
        }

        this.mp = mp; // 검사 통과 시 Wizard의 mp 필드에 저장
    }

} 

# getter and setter
    - 해당 본문은 필자가 이해한 getter, setter의 내용이다.

    - getter
            - private으로 선언된 변수는 클래스 외부에서 직접 접근할 수 없다.
            - getter는 이렇게 숨겨진 값을 외부에서 "읽을 수 있도록" 허용하는 통로다.
             - getter가 없다면 외부에서는 private 변수의 값을 직접 읽을 수 없다.

            public String getName() {
                return name;
            }

            위의 코드는 외부에서 getName()을 호출하면 객체 내부에 저장된 name 값을 읽어서 사용할 수 있도록 허용하는 코드이다.

    - setter
            -  private으로 선언된 변수는 클래스 외부에서 직접 접근 및 수정할 수 없다.
            -  setter는 수정과 기입이 제한된 정보들을 외부에서 "수정할 수 있도록" 허용하는 통로다.
            -  setter가 없다면 외부에서는 private 변수의 값을 직접 수정할 수 없다.
            -  setter 내부에 조건문을 넣어 값이 특정 조건을 만족할 때만 변경되도록 제어할 수 있다.
            -  잘못된 값이 들어오면 수정을 거부하거나 예외를 발생시킬 수도 있다. (위 조건문의 다른 말이다. 다만 조건문의 심화버전도 가능하다는 식으로 이해했다.)
            -  또 굳이 수정받을 필요가 없을때는 setter를 작성하지 않을 수도 있다. (생년월일, 성별, 국가 코드 등은 setter를 받을 필요가 없음으로 이해했다.)

# 클래스와 친구들, 넌 누구냐
    - 해당 본문은 필자가 조금 더 클래스에 대한 이해를 추구하기에 지난화의 복습과 같이 이해의 용도로 작성했다.

            클래스 Wizard
                   │
        ┌──────────┼──────────┐
        ↓          ↓          ↓
      필드        생성자       메서드
    (데이터)     (초기설정)     (기능)
        │          │          │
      name      Wizard()    attack()
      hp                    getName()
                            setHp()

            
            - 클래스 = 객체를 만들기 위한 설계도
            
            - 필드(Field) = 객체가 가지고 있는 정보 
            
            - 생성자(Constructor) = 객체의 탄생과 초기 설정
                - 생성자는 외부에서 변수를 받아올 수 있는 칸을 셋팅해놓음. String, int 이렇게 두개면 외부에서 이 두개를 입력할 수 있게 됨 

            - 메서드(Method) = 객체가 할 수 있는 기능/행동  
                - getter, setter는 메서드에 속한다. 클래스가 할 수 있는 공격, 스킬, 이동 등을 여기서 할 수 있음
