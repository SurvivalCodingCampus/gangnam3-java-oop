### 다형성

- **개념** : **무늬(참조 변수)는 하나**지만 **실체(인스턴스)에 따라 행동이 다양**하게 나오는 것
- **장점** :
    - **결합도를 낮추고 독립성을 높여** 변경에 강한 구조를 만듦
    - **공통 인터페이스**를 통해 **일관된 방식으로 객체들을 제어**할 수 있어 중복 코드가 줄어듦

- **단점** :
    - 인터페이스와 클래스 **구조가 복잡**해지면 **코드 흐름을 파악하기 어려울 수 있음**
    - **실행 시점에 실제로 어느 메서드가 호출되는지 확정**되므로 디버깅 시 **추적이 까다로울 수 있음**
    - **동적 바인딩 및 가상 함수 테이블(VTable)**[^2] 참조로 인해 정적 호출에 비해 약간의 실행 시간이 추가

#### 오버라이딩

- 상속/인터페이스 기반
- **상위 클래스**나 **인터페이스**에 정의된 **메서드**를 **하위 클래스**에서 **재정의**하는 것
- **런타임**에 **실제 참조하는 객체의 메서드**가 호출됨(동적 바인딩)
- 동적 다형성

#### 오버로딩

- 같은 이름의 메서드를 **매개변수의 타입이나 개수를 다르게 하여** 여러 개 정의하는 것
- **컴파일 시점**에 어떤 메서드가 호출될지 결정(정적 바인딩)
- 정적 다형성

### 자바 컬렉션

- 여러 개 데이터를 **하나의 단위로 묶어서 효율적으로 관리**(추가, 삭제, 검색, 정렬 등)할 수 있도록 제공하는 표준화된 **클래스 및 인터페이스의 집합**
- 레퍼런스 타입만 지원(**기본타입 박싱 언박싱 발생**)

#### 박싱 언박싱

- **기본 타입(Primitive Type)**과 이를 객체로 감싼 **참조 타입(Wrapper Class)** 사이에서 일어나는 데이터 형변환을 말한다
- Wrapper Class는 불변 객체다 **값을 변경하면 새로운 인스턴스를 만든다**
- **언박싱** : 래퍼 클래스 객체에서 **기본 타입의 값을 꺼내는** 것
- **박싱**
    - 기본 타입의 값을 래퍼 클래스의 **객체로 변환**하는 것
    - 변환하는 과정에서 인스턴스를 생성(참조가 끊어지면 가비지 생산)

#### Collection 인터페이스

- 리스트, 세트, 큐가 확장해 자료구조를 변경하더라도 기존 로직을 수정을 최소화
- 맵은 **Key-Value** 구조로 **Collection** 인터페이스를 **상속받지 않음** (독립적)

#### Collections 클래스

- **Collection 인터페이스**를 객체에 대해 알고리즘과 유틸리티 메서드를 제공
- **Collection 및 List** 객체들을 다루기 위한 **유틸리티/알고리즘 클래스**
- `max()`, `min()`, `synchronizedCollection()` 등은 `Collection` 전체에 적용 가능
- `sort()`, `reverse()`, `shuffle()` 등 인덱스 기반 조작은 **`List` 인터페이스 구현체만 가능**

#### 리스트 인터페이스

- 데이터의 **순서가 유지**되며 **중복 데이터 저장을 허용**

- **주요 클래스** :
    - **LinkedList** : **이중 연결 리스트** 기반, 데이터의 중간 삽입/삭제가 빈번할 때 유리
    - **ArrayList** :
        - **동적 배열** 기반, 인덱스를 통한 조회 속도가 매우 빠름 ($O(1)$)
        - default 배열 크기 10
        - 11번째 데이터를 넣으려는 순간 **1.5배**로 늘어남

#### 맵 인터페이스

- **Key(키)와 Value(값)의 쌍**으로 저장되며 **Key는 중복될 수 없고 Value는 중복 가능**
- **주요 클래스** :
    - **TreeMap** : **레드 블랙 트리** 기반, Key를 기준으로 자동 정렬되는 Map
    - **HashMap** :
        - **HashMap** 기반 키 기반, 검색 속도가 매우 빠름 ($O(1)$)
        - 엔트리수가 의 현재 용량의 **75%를 초과하면** 버킷이 **2배**로 증가
        - 충돌이 없으면 인덱스에 저장
        - 충돌이 발생하면 충돌한 인덱스에 우선
          오버헤드가 적은 단일 LinkedList를 이어 붙인다 $O(N)$
        - **충돌이 8개 이상이고 버킷의 크기가 64 이상이면
          LinkedList를 레드-블랙 트리 구조로 변환한다 $O(\log N)$

#### 세트 인터페이스

- 데이터의 **순서를 보장하지 않으며 중복 데이터**를 허용하지 않음
- **주요 클래스** :
    - **TreeSet** : **레드 블랙 트리** 기반, 데이터가 자동으로 오름차순 정렬됨
    - **HashSet** : **HashMap** 기반, 순서 없이 빠른 저장/검색 지원 ($O(1)$)
        - 내부적으로 **HashMap**을 사용해 **충돌 해결 알고리즘은 HashMap과 같다**
        - **HashMap의 Key**의 공간만 활용하고 **Value에는 Dummy객체**를 채우는 방식

### 양방향 이중 연결 리스트 (Doubly Linked List)

- **노드(Node)**들이 **앞뒤로** 서로 연결되어 있는 **선형 자료구조**
- **단방향 연결 리스트와 달리** **이전 노드(Prev)와 다음 노드(Next)**의 메모리 주소를 모두 저장

- **특징** :
    - **양방향 순회**가 가능
    - 특정 노드의 참조(주소)를 알고 있다면 **$O(1)$의 시간 복잡도**로 노드를 **삽입하거나 삭제** 가능

- **장점** :
    - 이전 노드로 이동하는 탐색이 쉬움
    - 양끝(Front/Back) 요소 **접근 및 삭제가 빠름**

- **단점** :
    - 각 노드마다 **참조를 2개씩** 가져야 하므로 메모리 오버헤드가 발생
    - **특정 위치(인덱스)의 데이터를 찾으려면** 처음이나 끝부터 순회해야 하므로 **탐색 성능은 $O(N)$**

### HashMap (해시맵)

- 키(Key)와 값(Value)의 쌍을 저장하는 자료구조
- **해시 함수(Hash Function)를 사용**하여 **키를 배열의 인덱스로 변환**해 데이터를 저장

- **구조** : `Key → [Hash Function] → Hash Code(Index) → Value`
- **특징** :
    - **키의 중복을 허용하지 않으며 값은 중복 가능**
    - 데이터의 순서를 보장하지 않는 것이 일반적
    - **해시 충돌(Hash Collision)** : 서로 **다른 키가 동일한 인덱스로 변환**되는 상황을 대비해 **체이닝(Chaining, 연결 리스트/트리로 연결)이나 개방 주소법(Open Addressing)**[^3] 등의 기법을 사용

- **시간 복잡도** :
    - 평균적으로 검색, 삽입, 삭제 모두 $O(1)$
    - 충돌이 최악으로 발생하는 경우
        - 연결리스트, 개방 주소법 $O(N)$
        - 레드-블랙 트리 $O(\log N)$

- **장점** : 데이터의 양과 상관없이 **검색 및 수정 속도가 매우 빠름**
- **단점** : **해시 충돌이 자주 발생하면 성능이 저하**되며 정렬된 순서대로 데이터를 순회하기 어려움

### 레드-블랙 트리 (Red-Black Tree)

- **자가 균형 이진 탐색 트리**(Self-Balancing Binary Search Tree)의 일종으로 노드가 **Red** 또는 **Black**의 색상 속성을 가짐

- **특징** :
    - 이진 탐색 트리(BST)는 편향 트리 $O(N)$가 될 수 있음 해당 단점을 극복
    - **데이터 삽입/삭제 시 특정 규칙에 따라 트리 회전 및 색상 변경을 수행**하여 트리를 **항상 $\log N$** 수준으로 유지

- **주요 규칙** :
    1.  모든 노드는 Red 또는 Black
    2. 루트(Root) 노드는 black
    3. 모든 NIL(리프) 노드는 Black
    4. Red 노드의 자식 노드는 모두 Black (Red 노드가 연속해서 나올 수 없음)
    5. 임의 노드에서 자손 nil 노드들까지 가는 경로들의 black 수는 같다(자신은 카운트에서 제외)

- **노드 x의 black height** : 노드 x에서 임의 자손 nil 노드 까지 내려가는 경로에서의 black 수
  5번 속성을 만족해야 성립

- **시간 복잡도** : 검색, 삽입, 삭제 모두 최악의 경우에도 $O(\log N)$을 보장
- **장점** : **데이터가 빈번하게 삽입, 삭제**되어도 트리의 **균형을 유지**하여 **안정적인 탐색 성능**을 제공
