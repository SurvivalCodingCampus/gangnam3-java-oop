# 1. 배운 점

## 에이전트 브라우저

> **에이전트형 브라우저**는 단순 검색·요약을 넘어, **AI가 사람처럼 직접 클릭·입력하며 웹 작업을 대신 수행하는 브라우저**다.

- **Aside:** AI 중심의 독립형 브라우저. 로그인 세션을 공유하고, 백그라운드 탭에서 결제·이메일 정리·폼 작성 등을 자동 처리하며 민감 작업 시 승인을 요청함.
- **ego lite:** Claude Code 등 외부 개발 에이전트 연동에 특화된 브라우저. 작업 공간(Task Space)을 격리해 사용자 마우스 포커스를 뺏지 않고 터미널 에이전트와 함께 작동함.

## GIT

### 이슈

> 프로젝트 내에서 발생하거나 작업해야 할 모든 일과 문제점을 기록하고 논의하는 게시판/트래커

- **버그 제보 (Bug Report)**: "로그인 시 500 에러 발생함"처럼 발견된 오류 공유
- **기능 요청 (Feature Request)**: "다크모드 지원 추가해주세요" 같은 새로운 아이디어 제안
- **작업할 일 (Task)**: "회원가입 API 개발", "DB 스키마 변경" 등 개발자가 해야 할 작업 정의
- **질문 및 논의 (Discussion)**: 특정 기술 도입이나 구조 변경에 대한 팀원 간 토론
- 담당자 지정, 라벨 지정, 프로젝트 지정이 가능하다
- 이슈 상태 변경, 이슈 브랜치 생성 가능

### 위키

> 레포지토리 전용 내부/외부 전용 위키백과(문서 창고)

- **프로젝트 가이드**: 개발 환경 세팅 방법(`Setup Guide`), 코드 컨벤션 문서.
- **아키텍처 및 설계**: DB ERD 설명, 시스템 구조도, 도메인 용어집(Glossary).
- **온보딩 문서**: 신규 팀원이 들어왔을 때 읽어야 할 필수 가이드.
- **공개 레포지토리**: 기본적으로 누구나 읽을 수 있고, 권한 설정에 따라 전체 공개 편집 또는 팀원(Collaborator) 전용 편집으로 제한 가능.
- **비공개 레포지토리**: 해당 레포지토리에 읽기/쓰기 권한이 있는 멤버만 접근할 수 있음.

### 좋은 PR 작성 원칙

> 리뷰어가 **"무엇을, 왜, 어떻게 변경했는지"** 최소한의 맥락 확인만으로 빠르게 이해하고 검토할 수 있도록

- **작은 단위 (Small Scope)**: 하나의 PR에는 하나의 주제/기능만 담음 (커밋 30개, 파일 50개 수정된 대형 PR은 리뷰 불가능).
- **명확한 제목 (Clear Title)**: 어떤 작업인지 직관적으로 작성 (컨벤션 적용).\
- **충실한 본문 (Structured Description)**: 배경, 변경 사항, 테스트 방법, 캡처 화면 첨부.
- Merge된 브랜치는 삭제
### GitFlow

- **`master` (또는 `main`)**: 제품으로 출시되는 최종 배포 버전 브랜치. 태그(Tag)로 버전을 기록함.
- **`develop`**: 다음 배포를 위해 개발 중인 코드가 모이는 메인 통합 브랜치.
- **`feature`**: 새로운 기능을 개발할 때 `develop`에서 분기하는 브랜치. 개발 완료 후 `develop`으로 병합.
- **`release`**: 배포 직전 최종 테스트와 버그 수정을 진행하는 브랜치. 배포 후 `master`와 `develop` 양쪽에 반영.
- **`hotfix`**: 운영 중인 서비스(`master`)에 긴급한 버그가 발생했을 때 수정하는 브랜치. 수정 후 `master`와 `develop`에 모두 병합.

- **1. 조직 (Organization)**
  - 여러 사람이 모여서 팀이나 기업 단위로 레포지토리와 멤버를 관리하는 **공유 계정 공간**.
  - 팀원별 권한(Admin, Write, Read 등) 설정이나 팀(Team) 그룹화를 통해 접근 제어를 할 때 사용함.

- **2. 레포지토리 (Repository, Repo)**
  - 실제 **코드, 파일, 커밋 히스토리, 브랜치**가 저장되는 기본 단위 공간 (프로젝트 폴더).
  - 하나의 앱이나 라이브러리, 프로그램마다 레포지토리가 하나씩 생성됨.

- **3. 프로젝트 (Project, Projects v2)**
  - 레포지토리에 흩어져 있는 이슈(Issue)와 PR(Pull Request)을 모아서 칸반 보드, 테이블, 로드맵 형태로 관리하는 작업/일정 관리 도구 (Jira나 Trello 같은 역할).
  - 조직(Org) 단위나 개인(User) 단위로 생성해서 여러 레포지토리의 진행 상황을 한눈에 추적할 때 사용함.

- 프로젝트: 여러 레포 지정하면 프로젝트에서 한 번에 볼 수 있음
