## 1. 배운 점

- **GIT PR 할 땐 브랜치명 영어**로 하는게 좋음 한글 브랜치로 PR 시 베이스 브랜치 변경 불가
- `마커 인터페이스`: 내부에 메서드나 상수가 전혀 선언되어 있지 않은 **빈 인터페이스**
  - `표식(Tag) 역할`: 클래스가 특정 속성, 규약, 또는 기능을 가지고 있음을 **컴파일러나 런타임(JVM)에 알리는 메타데이터 역할**
  - `instanceof` 연산자 등을 활용해 특정 **인터페이스를 구현한 클래스들만 묶어서 처리**할 수 있음
- `statements 랑 expression 차이`
  - **Expression (식):** 실행된 후 **하나의 결과값**을 만들어냄
  - **Statement (문):** 작업만 수행할 뿐 **결과값이 없음**
### 코틀린

- `프로퍼티` : 클래스 내부에 선언하는 **필드(멤버 변수)**와 그 값을 읽고 쓰기 위한 **접근자(Getter와 Setter)**를 하나로 묶어 제공하는 개념
  - `val`: 읽기 전용 (`field` + `getter`)
  - `var`: 가변 변수 (`field` + `getter` + `setter`)
- `기본 접근 제한자` : 자바의 기본 접근 제한자는 `package-private`이지만, 코틀린은 기본적으로 `public`
- `companion object` : 자바의 `static` 키워드를 대체하는 코틀린의 개념
  - 클래스 인스턴스 생성 없이 `클래스명.멤버` 형태로 직접 호출
  - 단순 `static`과 달리 인터페이스를 구현하거나 상속을 받는 등 진짜 객체(Object)처럼 동작
- `const val` : `val`은 프로그램 실행 중(런타임)에 값이 결정될 수 있는 반면, `const val`은 **컴파일 시점에 값이 결정되는 완전한 정적 상수**
  - Primitive 타입(Int, Double 등)과 String 타입에만 사용할 수 있음
  - `companion object` 내부나 파일 최상단(Top-level)에만 선언 가능
- Unit : 자바의 `void`에 해당
- 반환값이 없는 함수의 기본 반환 타입이며, 생략 가능
- `스마트캐스팅`: 타입 검사(`is`)를 마친 변수를 **개발자가 직접 형변환하지 않아도 컴파일러가 자동으로 형변환**
  - `if (x is String)` 검사를 통과하면, 해당 블록 안에서 `x`는 자동으로 `String`으로 취급되어 문자열 메서드를 바로 사용 가능
  - `null` 체크(`if (x != null)`)를 마친 변수도 자동으로 non-null 타입으로 스마트 캐스팅
- `백틱(``)을 활용한 함수명 정의` : 코틀린에서는 **백틱(\`\`)으로 감싸면 띄어쓰기나 특수문자가 포함된 이름을 함수명**으로 사용 가능
  - 주로 **테스트 코드**에서 테스트 케이스의 의도를 한눈에 알기 쉽고 설명적인 이름으로 작성할 때 사용
