## 1. 배운 점

### DataSource 패턴

> **DataSource 패턴**은 애플리케이션의 비즈니스 로직(UI나 도메인 영역)과 **데이터를 가져오는 출처(Database, Network, File, Local Cache 등)를 분리**하기 위한 아키텍처 패턴

- 데이터를 어디서 가져오는지(출처)에 대한 구체적인 구현을 숨기고 일관된 인터페이스를 통해 데이터를 주고받을 수 있게 만들어 줌

#### 구조와 역할

1. **DataSource Interface (`ItemDataSource.kt`)**
    - 데이터를 어떻게 가져오고 저장할지에 대한 규격을 정의함
    - 비즈니스 로직은 데이터가 파일에 저장되는지 네트워크를 통해 오는지 알 필요 없이 이 인터페이스만 바라보고 코드를 작성할 수 있음

2. **Concrete[^1] DataSource (`FileItemDataSource.kt`)**
    - 인터페이스를 실제로 구현하는 클래스
    - 이미지 예시에서는 파일 시스템을 다루고 있으나 필요에 따라 네트워크나 로컬 DB 구현체로 교체할 수 있음

#### DataSource 패턴의 장점

- 나중에 데이터 저장소를 변경하더라도 상위 비즈니스 로직을 수정할 필요 없이 새로운 구현체만 갈아 끼우면 됨
- 실제 파일이나 네트워크 접근 대신 인터페이스를 가짜(Mock) 객체로 대체하여 단위 테스트를 쉽게 작성할 수 있음
- 데이터 수집 및 관리 로직이 UI나 비즈니스 로직과 분리되어 코드가 깔끔해짐
