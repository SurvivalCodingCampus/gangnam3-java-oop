# Result 패턴

## 용어 정리

- `Result 패턴`: 여러가지 종류의 성공과 실패를 처리하기 용이한 패턴
- `sealed class`: 서브타입을 봉인. 패턴 매칭을 활용하여 모든 서브타입에 대한 처리를 하기 용이

## 클래스 작성 테스트 코드

```kotlin
class PokeRepositoryImplTest {

    @Test
    fun `포켓몬 검색 성공 시 Success와 데이터가 반환된다`() = runTest {
        // given
        val repository = PokeRepositoryImpl(FakePokeDataSource(statusCode = 200, body = PokeDto(name = "ditto")))

        // when
        val result = repository.getPoke("ditto")

        // then
        assertTrue(result is Result.Success)
        assertEquals("ditto", (result as Result.Success).data.name)
    }

    @Test
    fun `네트워크 연결 실패 시 Error와 NO_INTERNET이 반환된다`() = runTest {
        // given
        val repository = PokeRepositoryImpl(ErrorPokeDataSource(SocketException()))

        // when
        val result = repository.getPoke("ditto")

        // then
        assertTrue(result is Result.Error)
        assertEquals(NetworkError.NO_INTERNET, (result as Result.Error).error)
    }

    @Test
    fun `존재하지 않는 포켓몬 검색 시 CLIENT_ERROR가 반환된다`() = runTest {
        // given
        val repository = PokeRepositoryImpl(FakePokeDataSource(statusCode = 404, body = null))

        // when
        val result = repository.getPoke("dittooo")

        // then
        assertTrue(result is Result.Error)
        assertEquals(NetworkError.CLIENT_ERROR, (result as Result.Error).error)
    }
}
```

## 정리

- `서버에 데이터 요청 시 예상되는 상황`
  - 성공(Success)
  - 실패(Error, Failure): 실패의 종류가 하나가 아니다.
    - 네트워크 연결이 아예 안 되어 있음
    - 네트워크 불안정으로 타임아웃 발생
    - 논리적으로 잘못된 값

- `예외 처리`
  - 기본적으로 예외는 `try-catch` 를 활용하여 처리한다.
  - 그러나 런타임 에러 뿐만 아니라 논리적인 오류나 예외 상황에 대한 처리를 하기에는 부족하다.
  - `Result` 패턴은 성공, 실패 시 처리에 유용한 패턴이다.

- `Result 클래스 예시`
  - `Result` 클래스는 성공 시에는 데이터를, 실패 시에는 에러 정보(Exception, String 등)를 담는 객체를 정의한다.
  - `sealed class` `sealed interface` 는 타입 봉인 효과를 가진다.
  - `Unit` 은 정상 종료, `Nothing` 은 비정상 종료(예외 또는 무한루프)를 의미한다.
  - `Kotlin` 1.5부터는 `sealed interface` 를 사용하면 더 간결하고 유연하게 사용할 수 있다.
  - `Result` 로 감싸서 2가지 이상의 에러를 리턴 가능하다.

```kotlin
sealed class Result<out D, out E> {
    data class Success<out D>(val data: D): Result<D, Nothing>()
    data class Error<out E>(val error: E): Result<Nothing, E>()
}
```

```kotlin
sealed interface Result<out T, out E>

data class Success<out T>(val value: T) : Result<T, Nothing>
data class Error<out E>(val error: E) : Result<Nothing, E>
```

- `에러 타입 정의`
  - 필요한 에러를 정의한 `enum` 또는 `sealed class` 를 준비하면 더 디테일한 에러 핸들링이 가능하다.

```kotlin
enum class NetworkError {
    NO_INTERNET, // SocketException
    SERVER_ERROR, // 5xx
    CLIENT_ERROR, // 4xx
    TIMEOUT, // 타임아웃
    UNKNOWN // 기타 예외
}
```

- `Result 패턴 사용 시 장점`
  - 타입 안전성이 향상된다.
  - 명확한 분기 처리가 가능하다.
  - 에러 처리 누락 방지를 유도한다. (when 패턴 매칭)
  - 테스트 코드가 직관적이고 쉬워진다.
